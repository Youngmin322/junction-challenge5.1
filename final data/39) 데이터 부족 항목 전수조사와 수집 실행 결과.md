# 데이터 부족 항목 전수조사와 수집 실행 결과

> [!abstract] 결론
> 현재 공개자료로 구현 근거가 확보된 범위는 **해파리 관측·신고의 수신, 공개 표층유동장을 이용한 조건부 이동 계산, 출처가 명확한 `DEMO` 구역과의 교차, 데이터 건강상태 표시**까지다. 현재 설비의 취수 포획영역, 해파리 유입량, 스크린 차압, 원전 운전영향, 현장에 실제로 유용한 선행시간은 공개자료만으로 확정할 수 없다. 따라서 Act 1차 버전은 `원전 정지위험 예측`이 아니라 **관측·수송·구역교차의 근거를 한 화면에서 조회하는 검증용 대시보드**로 한정한다.

> [!success] 2026-08-22 추가 팀 결정
> MVP 대상 부지는 **한울 원전**으로 확정했다. 한울 인근 `HB_0007 한수원_온양`, `HB_0008 한수원_덕천`, `HB_0009 한수원_나곡` 점관측에서 유향·유속·수온을 받을 수 있어 후보 부지 중 현장과 가장 가까운 공개 해상자료로 현재상태와 모델을 검산할 수 있기 때문이다. 월성·포항 이중데모는 MVP 기본범위에서 제외한다.

> [!warning] 제출 12시간 전 검증전략 변경
> 원전 관계자·어민·관측기관을 새로 모집하거나 인터뷰하고, 기관에 자료를 요청해 회신을 기다리는 활동은 제출 전 실행범위에서 제외한다. 남은 시간에는 **트랙 제공자·해커톤 관계자의 짧은 확인, 공식 공개자료와 AI를 이용한 데스크 리서치, 팀 내부 블라인드 과업테스트, API·데이터·실패경로 검증**만 수행한다. 직접 사용자 검증과 시설자료 확보는 제출 후 검증부채로 남기며, 발표에서 완료했다고 주장하지 않는다.

이 문서는 [[37) 원전 취수구 해파리 위험 대시보드 서비스 계획서]], [[38) 동적 취수구 유입 위험영역 산정 설계]], [[36) 기존 해파리 직접관측 수신 데이터 감사]], [[35) 해파리 군집 위치 탐지 방법과 정보 결합 Investigate]], [[30) P0 질문 조사 답변과 미해결 항목]]에서 `미확보·미검증·가정·P0·N/A·계산 보류`로 남은 내용을 다시 추출해 중복을 합친 원장이다. 조사로 답할 수 있는 것은 바로 조사했고, 외부 권한이나 팀 결정이 필요한 것은 실제 요청 가능한 수집 티켓으로 바꿨다.

## 1. 이번 전수조사의 원칙

1. 팀 결정에 따라 종명은 MVP 입력에서 `해파리`로 묶는다. 단, 서로 다른 종의 밀도·행동·시설영향 임계값이 같다고 가정하지 않는다.
2. 대상 부지는 한울로 고정하고, 한울 인근 점관측은 현재상태·검산에 사용한다. 점관측을 한울 앞바다 면 유동장으로 보간해 대신하지 않는다.
3. `직접관측`, `조건부 위치추정`, `시설영향`을 한 위험확률로 합치지 않는다.
4. 공개자료로 찾을 수 없는 내부 운전값은 억지로 추정하지 않고 `제출 전 확인 불가·제출 후 검증부채`로 남긴다.
5. 같은 자료를 모델 입력과 정답으로 동시에 사용하지 않는다.
6. `미신고`는 `해파리 없음`이 아니다. 조사노력과 범위가 기록된 `미탐지`만 음성관측 후보로 본다.
7. 실제 좌표·도면·임계값처럼 보안 또는 운영 민감성이 있는 정보는 원자료가 아니라 비민감 구간값, 익명 구역 ID, 교차 결과를 우선 요청한다.

> [!warning] 구현 자산 판정
> `final data`에 실행 가능한 것으로 확인된 것은 legacy 해류 수집 Python과 CSV뿐이다. 해파리 관측수신 API, 예측엔진, 영향권 엔진, 대시보드, Copilot agent, 테스트는 아직 구현물이 아니다. 설계문서를 “이미 보유한 파이프라인”으로 발표하지 않는다.

판정은 `확인`, `부분 확인`, `미확인`, `팀 결정`, `외부 권한 필요`로 통일했다.

### 5.2 해류 API 실호출

- HF_0071은 98개 표층 격자를 반환했지만 포항항 주변 약 36.019–36.089°N 범위에 한정됐다.
- 2026-08-22 호출 당시 최신 시각이 2026-08-19 14:00으로 정체돼 있었다.
- HF_0073은 최신 시각 1행을 반환했으나 좌표·유향·유속이 비어 있어 사용 불가였다.
- 한울 인근 legacy 점관측 `HB_0007·HB_0008·HB_0009`는 유향·유속·수온을 반환했다. ROMS 검산 후보로는 유용하지만 면 유동장이 아니므로 단독 입자추적 입력으로 쓰지 않는다. 월성의 동급 근접점은 이번 조사에서 확인하지 못했다.
- KHOA는 2026-01-12 기존 35종 서비스를 폐기·대체한다고 공식 공지했다. 따라서 legacy 성공응답은 운영 지속성을 보장하지 않는다.
- 신규 ROMS를 한울·월성 bbox로 호출했지만 현재 키에는 서비스 권한이 없어 403 응답을 받았다.

### 5.3 해파리 관측 데이터 계보

## 6. 수집 티켓과 12시간 실행 우선순위

아래는 “추가 조사 필요”를 실행 가능한 티켓으로 바꾼 것이다. `T-01a·T-05·T-06`과 아래의 데스크 검증은 제출 전 실행한다. 기관 회신이 필요한 `T-01b·T-02·T-03`은 제출 후 검증부채이며 현재 구현의 전제조건으로 두지 않는다.

### T-01a KHOA 신규 ROMS 권한·실호출 — 제출 전

**요청 대상:** 국립해양조사원/공공데이터포털

**실행 내용**

1. 신규 ROMS 개발계정 활용승인
2. 한울 bbox 실호출과 응답 schema·시각·결측·커버리지 자가감사
3. `crdir`를 알려진 조류예보 시계열과 벡터 대조 검산
4. HB_0007·0008·0009 점관측과 방향·신선도 대조

**완료 증거:** 한울 bbox 24시간 raw response, HB 점관측 대조, schema snapshot, 결측·지연 보고서

### T-01b KHOA 데이터사전 문의 — 제출 후

**문의 내용:** `crdir` toward/from convention과 단위, 실제 격자간격·cadence·해안 결측, forcing 구성, 과거 run/hindcast, legacy 이후 HB 지점의 대체 endpoint·수심·유지 여부

> 제출 전에는 회신을 기다리지 않는다. T-01a의 명세·대조 검산으로도 방향을 확인하지 못하면 수송 패널을 `계산 보류`한다.

### T-02 NIFS 비식별 원시 관측 제공요청 — 제출 후

**요청 대상:** 국립수산과학원

**최소 필드**

`source_record_id, observed_at, received_at, lat, lon, location_accuracy, presence, count, area, size, evidence_available, observation_method, qc_status`

종명은 이번 MVP에서 일반 해파리로 묶어도 된다. 전화번호와 원본 개인정보는 요청하지 않는다. 좌표 공개가 어렵다면 격자 ID 또는 1–5km 축약좌표를 요청한다.

**함께 물을 것:** 저·고밀도 판정지침, 보고일과 실제 관측일의 차이, 중복 제거방법, 미탐지 기록의 의미

> 제출까지 12시간인 현재는 요청서 초안만 보존한다. 회신을 기다리지 않고 NIFS 공개 주간보고와 과거 좌표자료로 범위를 제한한다.

### T-03 KHNP 비민감 연구·운영자료 요청 — 제출 후

**요청 대상:** 한수원 한울본부·연구과제 담당/정보공개/협력 창구

**우선 요청**

1. 2021–2024 해양생물 실시간 모니터링·경보 과제의 비민감 결과보고서
2. 데이터사전, 성능평가 프로토콜, 운영 여부, 공개 가능한 API/샘플
3. 사건별 분 단위 값 대신 구간화한 `관측→확인→시설인지` 시간차
4. 비민감 범주의 차압 추세, 세척횟수, 수거량, 원인확인 여부
5. zone 좌표 대신 승인 `zone_id`와 교차 결과 제공 가능성

**요청하지 않을 것:** 상세 취수구·안전계통 도면, 보호계통 임계, CCTV 원본, 내부망·접근통제 정보

> 제출 전에는 한울본부 또는 원전 관계자에게 새로 접촉하지 않는다. 미공개 결과·운영값은 `N/A`로 유지한다.

### T-04 제출 전 데스크·프록시 검토

**검토자:** 트랙 제공자·해커톤 관계자, 구현에 참여하지 않은 팀원, 서로 다른 AI 모델

**검토 입력**

1. 한수원 `해수취수구담당` 공식 직무명세
2. 한울 1996·2003·2021·2024 공개 사건 타임라인
3. NIFS·KHOA 실제 데이터 필드와 결측·갱신상태
4. 직접관측/조건부 추정/DEMO zone/계산보류 화면
5. 발표 가능·금지문장 목록

**블라인드 과업**

1. 가장 최신 해파리 관측의 위치·시각·출처 찾기
2. 실측과 모델추정 영역 구분하기
3. 왜 수송계산이 보류됐는지 찾기
4. 특정 수치를 “확률”이라고 불러도 되는지 판정하기
5. 이 화면이 운전권고가 아니라 조회·확인 지원임을 설명하기

**완료 증거:** 과업 성공률, 잘못 읽은 필드, 출처 확인률, 허위 숫자 생성 여부, 트랙 제공자의 문제·데이터 적합성 코멘트

> 이 검토는 사용성·표현·근거추적의 오류를 찾을 수 있지만, 실제 원전 사용자의 수요·권한·필요 선행시간을 검증하지는 못한다.

## 9. 지금 만들 수 있는 것과 만들지 말아야 할 것

> G7 통과 여부와 무관하게 제출 전 프록시 검토는 실사용자 검증이 아니다. `실사용자 검증 완료`·`사용자 효과 입증` 표현은 항상 금지한다.

### 만들 수 있는 것

- 과거·수동 해파리 관측을 받는 표준 API와 provenance/QC
- legacy/cached 또는 신규 승인 후 공개 해류의 데이터 건강 패널
- 특정 관측점과 특정 표층 유동장을 조건으로 한 이동 envelope
- 출처가 표시된 DEMO zone과의 공간교차
- 직접관측점, 조건부 추정, no-data를 구분하는 지도
- 하위 데이터 API를 호출하고 근거를 요약하는 Copilot mock/검증 구조

### 아직 만들었다고 말하면 안 되는 것

- 현재 한울의 실시간 해파리 군집 위치
- 해파리 고밀도·대량발생 확률
- 취수구 도착확률·정확 ETA
- 시간당 유입량·스크린 적층량
- 차압 상승·감발·정지 확률
- 원전 운전·감발·정지 권고
- 현행 감시보다 빠르거나 피해를 줄였다는 성과

## 11. 최종 판정

> [!success] Investigate 산출물
> 데이터 부족은 이제 막연한 “자료가 더 필요함”이 아니라 ① 신규 해류 API 권한, ② 최신 좌표형 해파리 관측, ③ DEMO/시설 구역, ④ 실제 사용자와 선행시간, ⑤ 시설 시계열, ⑥ Copilot tenant 검증으로 분리됐다. 제출 전에는 ①–③·⑥의 기술·표현 검증만 수행하고, ④–⑤는 제출 후 검증부채로 남긴다. ①–③이 없으면 Act는 실시간 위험예측이 아니라 재현 가능한 데이터·공간교차 데모로 전환하며, ④–⑤가 없으므로 원전 업무효과·차압·정지확률을 주장하지 않는다.

현재 Act의 가장 안전하고 검증 가능한 서비스 문장은 다음과 같다.

> **공개·제보 기반 해파리 관측과 한울 인근 점관측·표층 해류를 조회해 조건부 이동영역과 명시적인 한울 확인구역의 교차를 보여주고, 데이터의 출처·신선도·불확실성을 함께 설명하는 취수업무 참고 대시보드.**
