# 기존 해파리 직접관측 수신 데이터 감사

> [!summary] 결론
> **해파리를 사람이 보거나 현장에서 채집한 결과를 받은 공개자료가 있으며, 종을 구분하지 않는다는 팀 합의 아래 실제 입력 후보로 사용할 수 있다.**
>
> - 좌표가 있는 36,826행 출현보고: 과거 해파리 위치자료로 사용 가능하며 경북 행은 3,177개, 그중 `경북 울진 원자력발전소 근해` 라벨은 136개다.
> - 375행 트롤조사: 종 구분을 유지한 과학조사 직접관측으로 보조 검증에 사용할 수 있다.
> - NIFS 주간보고·특보: 현장 모니터링을 집계한 최신 광역 관측정보다. 2026년 8월 14~20일 보고에는 포항 고밀도·영덕 저밀도 출현이 포함됐다.
> - 2025년 공개 `해파리신고` 파일: 실제 다운로드 결과 상세 신고행이 아니라 **게시물 5건짜리 샘플**이다.

> [!note] 팀 합의 적용
> 이번 MVP에서는 노무라·보름달물해파리 등 종을 하나의 `해파리 관측`으로 묶는다. 따라서 종명 누락은 사용 중단 사유가 아니다. 대신 결과는 `해파리 위치·이동 가능성`으로 표현하고 `노무라만의 예측 성능`이라고 부르지 않는다.

## 1. 이번 감사에서 말하는 직접관측

직접관측은 사람·카메라·음향·채집 등이 특정 시공간에서 해파리 또는 노무라입깃해파리를 실제로 확인한 기록이다. 해류·수온·기상·위성 해수면고도·입자추적 결과는 직접관측이 아니다.

이번 MVP의 위치추정 seed는 최소 `보고일자 + 위도·경도 + 해파리 출현`이면 허용한다. 사진·관측시각·방법·관측범위는 있으면 신뢰도를 높이는 선택 필드로 둔다.

| 필수축 | 최소 필드 |
| --- | --- |
| 관측 대상 | `해파리` 분류군. 종명은 선택 |
| 시공간 | 보고일자, 위도·경도. 실제 관측시각·수심은 선택 |
| 증거 | 관측법, 사진·영상·표본 또는 검증상태가 있으면 신뢰도 상향 |
| 양·노력 | 크기·밀집여부·개체수·관측범위가 있으면 신뢰도 상향 |
| 이력 | 접수시각, 제공자 유형, 원문, QC 상태 |

`미신고`는 `미발견`이 아니다. 음성 기록으로 쓰려면 언제 어디를 어떤 방법으로 얼마나 확인했는지가 있어야 한다.

## 3. 가장 중요한 원자료 감사

### 3.1 좌표는 있으나 종이 없는 출현보고 36,826행

[공공데이터포털 원문](https://www.data.go.kr/data/15147963/fileData.do)은 이 자료를 `해파리출현정보관리출현보고`라고 설명하고, 필드를 보고일자·지역·위도·경도·해파리크기·밀집여부로 명시한다.

실제 파일 감사 결과:

- 행 수: 36,826
- 실제 날짜: 2013-07-25~2019-07-11, 189개 날짜
- 좌표 완전 행: 36,600
- `경북` 문자열 행: 3,177, 188개 날짜, 2,766개 고유 날짜-좌표
- `경북 울진 원자력발전소 근해` 라벨: 136행
- 종명, 사진, 관측방법, 관측범위·노력, 신고자 유형 필드: 없음
- 전체 완전중복: 5,287행
- 경북 행 중 위도·경도가 뒤바뀐 것으로 보이는 행: 111행

따라서 이 자료를 `그 날짜·점에서 해파리 출현이 보고됨`이라는 역사 관측 seed로 사용한다. 팀이 종을 묶기로 했으므로 종명 누락을 이유로 제외하지 않는다. 중복을 제거하고 좌표가 뒤바뀐 행을 교정하거나 제외하는 최소 정제만 수행한다. 결과 역시 특정 종이 아니라 `해파리`에 한정한다.

또한 공식 페이지의 `수집방법`이 비어 있어 이 36,826행이 NIFS 모니터요원의 어떤 접수 절차를 거쳤는지까지는 공개 메타데이터만으로 확정할 수 없다.

### 3.2 종과 조사노력이 있으나 경북이 없는 트롤 375행

[공공데이터포털 원문](https://www.data.go.kr/data/15147957/fileData.do)은 트롤어업 방식으로 해파리의 양과 분포를 조사한 자료라고 설명한다. 투망·양망 시각과 위치, 수심, 종명, 우산크기, 개체수, 개체/m³가 포함되므로 직접 제보보다 관측방법과 노력량이 분명하다.

실제 파일 감사 결과:

- 행 수: 375
- 실제 기간: 2011-06-14~2023-07-13 누적
- `노무라` 115행 + `노무라입깃해파리` 38행 = 153행
- 그중 좌표 완전 노무라 행: 136
- `없음`: 108행
- 경북 근사 영역의 노무라 행: 0

직접관측 데이터 품질은 네 후보 중 가장 높다. 경북 최신 위치 입력은 아니지만, 출현·미출현과 관측노력을 함께 다루는 데이터 구조를 만드는 데 사용할 수 있다. 375행을 `2023년 단년 데이터` 또는 `경북 자료`라고 부르지는 않는다.

### 3.3 현장관측을 받아 만든 NIFS 주간 집계

NIFS는 해파리 모니터요원을 어민·지자체·국가공무원 등으로 구성하고, 공식 페이지에 총 294명·경북 45명을 제시한다. 따라서 **현장관측을 수신하는 제도적 체계는 이미 존재한다.** [NIFS 해파리 모니터요원](https://nifs.go.kr/portal/pcon0000062/systA/actionConts.do)

현재 NIFS 웹 신고폼도 사진, 발견위치, 위·경도, 출현면적, 면적당 마리수, 크기와 기타내용을 실제로 받는다. 즉 팀이 구상한 현장관측 수신 구조와 유사한 체계는 이미 운영 중이다. 다만 이 개별 신고 원문을 우리 팀이 공개 API로 즉시 받을 권한은 확인되지 않았다. [NIFS 해파리 웹 신고](https://www.nifs.go.kr/portal/me/jelyB/actionJelyFormWrite.do)

다만 공개 [NIFS 해파리 OpenAPI](https://www.nifs.go.kr/openApi/actionOpenapiInfoList.do)의 `jellyDetail2`는 조사일시, 종별 시도 출현률, 출현해역 서술, 분포도, 발견률 등을 제공하는 주간 집계다. `nom_ratio_10`은 경북 노무라 출현률이지만 다음이 없다.

- 개별 신고의 위도·경도
- 실제 관측시각과 접수시각의 분리
- 사진·관측법·종 판정 신뢰도
- 관측한 범위와 미발견 노력

따라서 NIFS 주간자료는 포항·영덕 같은 **해안구간 단위 광역 seed**로 사용한다. 한 점에서 출발시키지 않고, 보고된 해안구간 안에 복수의 가상 시작점을 배치해 결과 범위를 넓게 표시한다.

최신 2026년 8월 14~20일 보고에는 어업인 모니터요원 270명의 응답이 취합됐고, 경북에서는 포항시 고밀도·영덕군 저밀도 출현이 보고됐다. 웹 신고 36건 중 경북 신고는 3건이었다. 이는 현재도 현장 관측 수신이 작동하며, 최소 시·군 해역 수준의 최신 입력을 얻을 수 있음을 보여준다. [NIFS 2026년 제16회 주간보고](https://www.nifs.go.kr/board/actionBoard0022View.do?MENU_ID=M0000121&BBS_ID=20260820132230110SLI&selectPage=1)

### 3.4 최신 `해파리신고` 공개파일의 착시

[NIFS 해파리신고 파일](https://www.data.go.kr/data/15145982/fileData.do)은 설명상 해파리 코드명·출현지역·신고건수를 포함한다고 되어 있다. 그러나 공개 CSV를 직접 내려받아 확인하면 다음 네 필드만 있는 5개 샘플 행이다.

```text
순번, 제목, 작성자, 작성일
```

제목도 `해파리 웹 신고 실시간 현황` 게시물이다. 즉 지금 공개된 파일은 신고 상세 테이블이 아니라 게시물 색인에 가깝다. 포털은 전체 자료가 필요하면 데이터 제공요청을 하라고 명시한다. 데이터셋 이름만 보고 `실시간 제보 위치 API가 확보됐다`고 판단하면 안 된다.

| 공간 성능검증 | 종·시간·좌표가 독립된 T0/T1 쌍을 새로 확보할 때 | 같은 주간보고를 입력과 정답에 동시 사용, 미신고를 음성으로 처리 |

## 5. 새로 수신해야 할 직접관측 계약

기존 자료보다 빠르고 정밀한 입력을 만들려면 팀의 API는 다음을 받는 것이 좋다. MVP 필수값은 `관측시각·위도·경도·해파리 출현`이고 나머지는 선택·품질평가 필드다.

```yaml
obs_id: string
observed_at: datetime
received_at: datetime
lat: number
lon: number
depth_or_range_m: string|null
taxon_raw: string
taxon_scientific: string|null  # 선택
species_confidence: unverified|photo_reviewed|expert_confirmed|sample_confirmed  # 선택
method: visual|photo|video|sonar|net|edna|facility_sensor
evidence_uri: string|null
count_or_density_value: number|null
count_or_density_unit: string|null
aggregation_class: none|scattered|patch|dense|unknown
effort_duration_min: number|null
survey_footprint: object|null
source_type: fisher|monitor|researcher|facility|public
qc_status: received|needs_review|approved|rejected
```

양성·음성은 다음처럼 기록한다.

- **양성:** 정의된 범위를 확인해 노무라가 관측되었고 종 판정 근거가 있음.
- **음성:** 정의된 범위를 실제로 확인했지만 노무라가 관측되지 않음. 관측법·시간·범위·가시성 필수.
- **미관측:** 확인하지 않았거나 확인범위를 모름. 음성으로 사용 금지.

## 6. 이번 조사로 수정되는 서비스 설명

`현장 관측정보를 수신한다`는 방향은 타당하다. 다만 기존 공공데이터가 이미 완전한 실시간 입력을 제공한다고 가정하면 안 된다.

> **NIFS의 해파리 광역 관측·특보와 과거 좌표형 출현보고를 출발 신호로 사용하고, 어민·조사기관·승인된 센서에서 새 현장관측을 수신할수록 위치 범위를 갱신해 다음 확인구역을 제시한다.**

이 문장은 팀이 직접 현장관측을 수행한다고 주장하지 않으며, 기존 집계자료와 새로 수신할 점 관측의 역할도 분리한다.

## 7. P0 후속 검증

1. NIFS에 36,826행 출현보고의 신고 주체·수집절차와 실제 관측일·보고일 차이를 확인할 수 있는가?
2. `해파리신고` 전체 데이터 제공요청으로 위치·신고시각·사진·건수 상세행을 받을 수 있는가?
3. NIFS 주간보고의 내부 점 관측을 비식별·지연 공개 형태로 제공받을 수 있는가?
4. 경북 모니터 45명의 신고가 어느 빈도·좌표정밀도·검증절차로 들어오는가?
5. 현장 파트너가 동일한 관측노력의 `발견`과 `미발견`을 함께 보낼 수 있는가?
6. 공개 또는 협약자료에서 최신 경북 노무라 T0 관측과 독립 T1 후속관측을 만들 수 있는가?

### 중단·전환 조건

- 최소한 날짜와 위치가 있는 해파리 관측을 확보하지 못하면 위치추정 기능을 실행하지 않는다.
- 관측법·범위가 없는 미신고 자료는 음성 라벨로 만들지 않는다.
- 경북·현재 시점의 독립 후속관측이 없으면 위치 정확도·도착확률·ETA를 주장하지 않는다.
- 공개자료만으로는 `원전 취수구 유입`, `생물량`, `스크린 부하`, `정지확률`을 출력하지 않는다.
