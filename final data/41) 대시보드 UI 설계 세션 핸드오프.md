# 대시보드 UI 설계 세션 핸드오프

> [!important] 수신 세션 요청
> 이 문서를 UI 설계의 working brief로 사용한다. 먼저 기존 결정과 표현 경계를 유지한 채 정보를 확인하고, 누락·충돌만 보고한다. 사용자가 UI 설계를 지시하기 전에는 제품 범위를 확장하거나 원전 전체 업무흐름을 새로 설계하지 않는다.

## 1. 프로젝트 한눈에 보기

- **해커톤:** Junction Asia 2026
- **트랙:** Microsoft Korea × 경상북도 공공데이터
- **지역 문제:** 경북 한울 원전 주변에서 대량 해파리 유입 가능성을 더 일찍 조회·확인할 수 있도록 공개 해양정보를 연결
- **MVP 부지:** 한울 원전 단일 부지
- **MVP 생물:** 종을 구분하지 않은 일반 `해파리`
- **1차 사용자 가설:** 한울의 해수취수구·가동 업무 관리자. 공식 직무문서 기반 가설이며 실제 사용자 검증은 아직 하지 못함
- **제품 형식:** 지도 중심의 상황인지·조회 대시보드 + 중앙 Copilot 질의 인터페이스
- **제품이 하지 않는 것:** 원전 운전·감발·정지 권고, 실제 취수구 막힘·차압·정지확률 예측, 원전 조직의 전체 업무·SOP 설계

### 서비스 한 문장

> **공개·제보 기반 해파리 관측과 한울 인근 점관측·표층 해류를 조회해 조건부 이동영역과 명시적인 한울 확인구역의 교차를 보여주고, 데이터의 출처·신선도·불확실성을 함께 설명하는 취수업무 참고 대시보드.**

## 2. 문제와 가치

해파리·살파·어군 등 대량 해양생물이 정상발전용 해수 취수·순환수 계통의 스크린과 여과설비에 부담을 주어 감발이나 보호정지를 유발한 국내외 사례가 있다. 그러나 개별 공개사례에서 원자로 안전기능 상실이나 방사선 사고가 확인된 것은 아니다.

우리 서비스의 가치는 `원전사고 예측`이 아니라 다음에 있다.

1. 흩어진 해파리 관측과 해류·기상자료를 한 화면에서 조회
2. 직접 관측과 모델 추정을 분리하면서 다음 확인 후보해역·시간창 제시
3. 데이터가 오래됐거나 계산조건이 부족하면 위험숫자를 만들지 않고 이유와 결손 표시
4. 사용자가 “왜 이 구역인가?”를 출처와 실행계보까지 확인

## 3. 현재 제품 범위

제품 흐름은 두 단계까지만 다룬다.

1. **평시 준비상태 확인:** 데이터 최신성·커버리지·직접관측·조건부 이동영역 조회
2. **신호 수신·검증:** 새 관측 QC → 수송 재계산 → 공개/DEMO 확인구역 교차 → 근거·상충·결손 설명

그 뒤의 인력배치, 원전 운전판단, 감발·정지, 복구·보고·교대흐름은 운영사의 기존 업무영역이다.

## 4. 한울 공개 데모의 공간 의미

공개형 MVP에서는 실제 취수구 위치·형상·흡입방향을 추정하지 않는다.

- `HB_0007 온양`, `HB_0008 덕천`, `HB_0009 나곡` 공개 해양관측점이 들어가는 ROMS wet cell을 **공개 감시게이트**로 사용
- 게이트는 취수구·스크린·호기별 도착면이 아님
- 화면에 발전소 핀과 관측소를 인과적으로 연결하는 선을 그리지 않음
- 정확한 시설 zone이 없으므로 `PUBLIC/DEMO GATE` 워터마크 상시 표시
- 기본 시간창은 한울 구현설계 기준 `6·12·24·48시간`

현재 기본모드는 신규 ROMS 한울 bbox 실호출이 검증되기 전까지 `CACHED/SYNTHETIC/BLOCKED` 중 하나다. 실제 데이터가 없을 때 LIVE처럼 보이게 만들지 않는다.

## 5. UI에서 반드시 분리할 네 가지 정보층

| 정보층 | 의미 | 권장 시각표현 | 금지 오독 |
| --- | --- | --- | --- |
| `direct_observation` | 실제·과거·수동 입력으로 받은 해파리 관측 | 불투명 점·선·면, 출처·관측시각 표시 | 주변 전체에 해파리가 있다는 뜻 아님 |
| `conditional_scenario` | 특정 seed와 표층 유동장을 조건으로 계산한 이동 envelope | 반투명 띠·입자·시간 슬라이더 | 존재확률·도착확률·정확 ETA 아님 |
| `context` | 수온·풍·파랑·데이터 상태 | 별도 레이어·상태카드 | 해파리 직접탐지나 위험가중치 아님 |
| `unavailable` | 자료부족·커버리지 밖·Gate 실패·미계산 | 회색 마스크·차단카드·명시적 사유 | `없음=안전`이 아님 |

데이터 모드는 별도로 `LIVE | CACHED | SYNTHETIC | BLOCKED`를 상단에 고정한다.

## 6. 권장 대시보드 정보구조

### 상단 상태바

- 대상: `HANUL / PUBLIC DEMO`
- 현재 데이터 모드
- 기준시각·마지막 갱신시각
- 관측·유동장·zone·수송 Tool 상태
- `계산 가능 / 부분 가능 / 계산 보류`

### 중앙 지도 — 화면의 60~70%

- 직접관측점과 관측범위
- 표층 해류벡터 또는 방향 미확인 상태
- 6·12·24·48시간 조건부 이동 envelope
- 온양·덕천·나곡 공개 감시게이트와 교차영역
- 데이터 커버리지 밖·미관측·자료부족 마스크
- 실데이터·과거재생·가상 시나리오 워터마크

### 우측 판단패널

- 시간창별 `M of N ensemble members intersected`
- 최초 교차 **시간창** — ETA라고 부르지 않음
- 선택한 관측·해류자료와 제외한 후보·이유
- 주요 가정·반대신호·자료결손
- “왜 이 구역인가?” Copilot 질의

### 하단 또는 상세 드로어

- 관측·해류·환경 시계열
- source URI, issued/valid/fetched time, checksum, run ID
- 선택정책 버전과 실행근거 묶음
- Tool 입력·출력·오류·재현 링크

## 7. Copilot·MCP 설계

MVP는 다수의 생성형 에이전트를 만드는 구조가 아니다.

> **중앙 Copilot 1개 + MCP 서버 1개 + 결정론적 MCP Tool 6개**

| MCP Tool | 역할 |
| --- | --- |
| `search_observations` | 해파리 관측 후보 검색·QC·선택·제외 내역 반환 |
| `get_field_status` | 해류장의 커버리지·신선도·방향 Gate를 계산 전에 판정 |
| `run_transport` | 검증된 seed·field로 표층조건부 수송 실행 또는 blocked 반환 |
| `list_zones` | 한울의 공개·DEMO zone과 버전 조회 |
| `intersect_zone` | 저장된 run과 zone을 결정론적으로 교차 |
| `explain_run` | 출처·가정·선택정책·오류·checksum의 evidence bundle 반환 |

관측·해류·환경·영향권·수송·검증은 별도 LLM 에이전트가 아니라 논리적 데이터 책임모듈이다. Copilot은 Tool을 선택하고 원 수치를 바꾸지 않은 채 결과·상충·결손을 설명한다.

### 데이터 선별 투명성

MCP 검색은 선택된 데이터만 반환하지 않는다.

- `query_echo`
- `candidates_scanned`
- `returned`
- `excluded_counts`와 사유
- `ranking_rule`
- `selected_sources[]`, `excluded_sources[]`
- `selection_policy_version`, `dataset_version`, `license`

`candidates_scanned = returned + Σexcluded_counts`를 만족해야 한다. LIVE가 없을 때 CACHED/SYNTHETIC으로 조용히 대체하지 않는다.

## 8. 공공데이터와 현재 한계

### 해파리 관측

- 과거 좌표형 출현보고: 36,826행
- 경북 문자열 기준: 3,177행
- `경북 울진 원자력발전소 근해` 라벨: 136행
- 한계: 종 필드 없음, 개별 시각·관측법·사진 없음, 중복과 좌표 뒤바뀜 QC 이슈
- NIFS는 현장 제보를 실제 수신하지만 최신 공개물은 주간·시군·도 집계 중심이며 실시간 점 API가 아님

### 해류·환경

- 한울 인근 공개점: HB_0007 온양, HB_0008 덕천, HB_0009 나곡
- KMA 죽변 연안부이: 풍·파랑·수온 문맥. 해류센서가 아님
- KHOA ROMS: 한울 면 유동장 후보. 권한·실응답·격자·방향 convention Gate를 통과해야 수송 활성화
- 점관측을 보간해 임의 면 유동장을 만들지 않음

### 시설 영향

- 실제 취수구 zone, 취수유량, 스크린 차압·세척·수거량은 없음
- 따라서 유입 kg/h, 스크린 폐색, 차압상승, 감발·정지확률은 UI에 만들지 않음

## 9. 표현 금지와 허용

### 허용

- `표층조건부 이동영역`
- `공개 감시게이트와 교차한 ensemble member M/N`
- `최초 교차 시간창`
- `직접관측 / 조건부 시나리오 / 환경문맥 / 자료부족`
- `계산 보류 — 면 유동장 미확보`

### 금지

- `한울 취수구 도착확률 82%`
- `6시간 뒤 도착 ETA`
- `해파리 때문에 원전사고 가능`
- `현재 군집 실시간 탐지 완료`
- `M/N = 실제 확률`
- `자료가 없으므로 안전`
- `AI가 원전 운전·정지 판단`
- `실사용자 검증 완료`

## 10. 심사기준과 UI 데모

트랙 제공자는 MCP 형식 자체보다 다음을 본다고 확인했다.

1. 경상북도 문제를 얼마나 유용하게 해결하는가
2. 다른 AI와 사용자가 결과를 신뢰할 수 있는가
3. 다른 AI와 사용자가 재사용할 수 있는가

60초 데모는 다음 세 장면을 UI에 반영한다.

1. **검색:** 울진 근해 해파리 관측 → 실제 경북 과거자료에서 선택·제외 내역 표시
2. **판단 또는 정직한 차단:** 6시간 확인후보 질문 → field가 ready면 수송·교차, blocked면 계산보류와 필요한 데이터 표시
3. **재사용:** 다른 MCP client에서 같은 refs로 동일 run ID·checksum·결과 재현

> UI가 원전 전체 대응 workflow, 담당자 배정, 감발·정지 추천, 실제 취수구 취약점 시각화로 확장되지 않도록 한다. 핵심 부피는 해파리 관측·표층조건부 수송·공개 감시게이트 교차·근거와 자료부족이다.
