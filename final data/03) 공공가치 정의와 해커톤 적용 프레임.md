# 공공가치 정의와 해커톤 적용 프레임

> [!summary] 이 해커톤에서의 작동 정의
> 경상북도의 실제 공공 수요를 특정하고, 공공데이터와 AI를 이용한 개입이 측정 가능한 지역 변화를 만들 잠재력이 있음을 근거로 보여주는 것.

## 작성 범위와 협업 방식

- Codex와 Claude가 `Codex-Claude 협업 프로토콜` v1.0 원문을 각각 직접 확인했다.
- 독립성·비용 등급: I1 역할 분리 / C1 일반 문서 분석
- Codex: 요구사항 고정, 공식 근거 확인, Evidence Ledger 작성, Claude 계획 교차검증, 최종 편집
- Claude: 요구사항 누락 검토, 사실 판정, 접근법과 실패 조건 설계
- 사실 검증과 해결안 설계를 별도 호출로 분리했다.
- Claude는 프로젝트 파일을 수정하지 않았다.
- Claude CLI의 비용 표시는 Max 구독 환경에서의 API 단가 환산 추정치이며 별도 청구액이 아니다.

## 1. 일반적으로 공공가치란 무엇인가

공공가치는 개인 고객 한 명의 만족이나 기업의 수익만으로 설명되지 않는 **공동체 차원의 바람직한 변화**다.

Mark H. Moore의 공공가치 이론은 시민이 맡긴 공적 자원과 권한을 사용해 공공의 위해를 줄이거나 공동의 이익을 증진하는 데 초점을 둔다. 이때 가치 제안만이 아니라 민주적 정당성과 지지, 실제 실행 역량을 함께 고려한다. 성과를 볼 때도 공동의 미션, 공정성, 이해관계자 경험, 미래 가치의 지속 가능성을 함께 본다.

HM Treasury의 Public Value Framework는 투입한 공공 자원 자체보다 그 자원이 실제 정책 결과로 전환되는지를 본다. 따라서 데이터·AI·화면은 가치 그 자체가 아니라 공공 결과를 만들기 위한 수단이다.

| 구분 | 의미 |
| --- | --- |
| 공공데이터 사용 | 재료 |
| AI 기능 | 수단 |
| 화면·분석 결과 | 출력 |
| 사람의 판단·행동 변화 | 결과 |
| 위험·비용 감소, 접근성·안전 향상 | 공공가치 |

### 일반 이론을 사용할 수 있는 범위

- 아이디어 발상과 사각지대 점검
- 누가 혜택에서 배제되는지 검토
- 정당성, 공정성, 신뢰, 지속 가능성에 대한 발표 질의 준비

### 사용하면 안 되는 방식

- 공정성·포용성·정당성을 트랙에 명시된 별도 가산 항목처럼 주장
- 일반 공공가치 이론을 공식 심사 문구보다 우선
- 이론적 가치만으로 실제 데이터·프로토타입 부족을 대체

## 2. 이 트랙에서 공식적으로 확인된 의미

Microsoft Korea 트랙의 공식 평가 항목은 **Public Value & Applicability 35%** 다. 슬라이드의 평가 설명은 다음 두 요소를 제시한다.

1. 실제 공공 수요를 해결할 잠재력
2. 측정 가능한 지역 영향을 만들 잠재력

여기서 중요한 단어는 **잠재력**이다. 해커톤 기간에 사회적 성과를 이미 대규모로 달성해야 한다는 뜻이 아니다. 대신 문제 근거, 실제 데이터 통합, 작동 프로토타입과 측정 설계로 인과관계를 설득해야 한다.

### 적용 가능성을 뒷받침하는 보조 증거

공식 슬라이드의 제출 조건과 운영 맥락에서 다음을 확인했다.

- 공공데이터 최소 1개를 기능에 실제로 사용
- 실제 데이터 통합이 없는 UI 목업 지양
- 원본 데이터의 무가공 노출 지양
- 비전문가도 배포·사용하기 쉬운 Ready to Run 결과물
- 작동 프로토타입에 추가 점수
- 인프라형은 GitHub 공개와 오픈소스 라이선스 명시

> [!warning] 해석 경계
> 위 항목은 적용 가능성을 설명하는 유력한 보조 증거지만, 공식 문서에서 35% 항목의 세부 배점으로 명시된 것은 아니다. 경상북도 저장소 이관도 운영 맥락이지 확인된 채점 항목은 아니다.

## 3. 공공가치 증거사슬

주제마다 다음 사슬을 한 문장씩 채운다.

| 단계 | 확인할 질문 | 가능한 근거 |
| --- | --- | --- |
| 직접 사용자 | 시스템을 실제로 조작하는 사람은 누구인가? | 역할·업무 관찰 |
| 최종 수혜자 | 결과로 삶이나 업무가 달라지는 사람은 누구인가? | 사용자·이해관계자 정의 |
| 공공 수요 | 어떤 불편·비용·위험이 얼마나 크거나 심각한가? | 공공데이터·공식 통계·현장 근거 |
| 공공데이터 | 어떤 데이터가 판단에 실제로 사용되는가? | 데이터셋 ID·API·파일 |
| 개입 | 기존 방식에서 무엇을 다르게 판단하거나 행동하게 만드는가? | 전후 업무 흐름 |
| 즉시 결과 | 시스템이 무엇을 분류·예측·추천·연결하는가? | 프로토타입 출력 |
| 지역 영향 | 시간·오류·위험·접근성·비용이 어떻게 달라지는가? | 영향 지표 |
| 측정 | 누가, 언제, 어떤 단위로 측정하는가? | 기준선·측정 계획 |

### 발표 문장 템플릿

> 경상북도의 `[최종 수혜자]`는 `[구체적 문제]`를 겪고 있으며, `[근거]`로 규모 또는 심각성을 확인했다. 우리는 `[공공데이터]`를 이용해 `[판단·행동]`을 바꾸고, 그 결과 `[지표]`가 `[기준선]`에서 `[목표]`로 변화할 잠재력을 `[측정 방법]`으로 검증한다.

### 근거 라벨

각 주장에 다음 중 하나를 표시한다.

- 공공데이터
- 공식 통계·문서
- 인터뷰·현장 관찰
- 프로토타입 자체 측정
- 추정

기준선은 반드시 공공데이터일 필요는 없다. 다만 출처, 표본, 관측 시점과 취득 방법을 밝혀야 한다.

## 4. 주제 후보 판정 기준

### 공식 게이트

다음 중 하나라도 충족하지 못하면 트랙 적합성을 다시 검토한다.

- [ ] 공공데이터 최소 1개를 기능에 실제로 사용하는가?
- [ ] 경상북도의 실제 문제를 다루는가?
- [ ] 단순 UI 목업이나 원본 데이터 조회를 넘어서는가?

### 팀 내부 판단 기준

다음은 공식 채점표가 아니라 후보 비교용 휴리스틱이다.

- [ ] 직접 사용자와 최종 수혜자를 구분할 수 있는가?
- [ ] 대상 집단이 구체적으로 식별 가능한가?
- [ ] 문제의 규모 또는 심각성 근거가 하나 이상 있는가?
- [ ] 공공데이터가 핵심 판단이나 행동에 실제로 필요한가?
- [ ] 사용자의 판단·행동이 어떻게 달라지는지 설명할 수 있는가?
- [ ] 측정 가능한 영향 지표와 기준선 확보 방법이 있는가?
- [ ] 개발자 도움 없이 대상 사용자가 핵심 과업을 완주할 수 있는가?
- [ ] 3일 안에 실데이터 기반 핵심 흐름을 구현할 수 있는가?
- [ ] 해커톤 이후 유지·이관 경로를 설명할 수 있는가?

점수 합계만으로 결정하지 않는다. 근거가 약한 항목을 표시하고 24시간 안에 보강 가능한지 판단한다.

## 5. 서비스형과 인프라형의 공공가치

### 서비스형

시민·공무원·사업자 등이 직접 사용하고 판단 또는 행동을 바꾸는 경로를 보여준다.

### 데이터 인프라형

직접 사용자는 개발자나 공무원일 수 있다. 이 경우에도 최종 수혜자와 공공 결과까지 이어지는 경로를 설명해야 한다. 다만 해커톤에서 시민 성과를 실제로 달성·입증해야 한다는 뜻은 아니며, 경로의 타당성과 측정 가능성을 제시하면 된다.

## 6. 피해야 할 안티패턴

- 일반 서비스를 만든 뒤 이름만 “경상북도용”으로 변경
- 공공데이터를 지도나 표에 표시하기만 함
- AI 기술의 복잡성을 공공가치로 설명
- 수혜자를 “경북 도민 전체”라고만 표현
- 화면 출력 수나 조회 수를 지역 영향으로 주장
- “편의성 향상”처럼 단위와 측정 주체가 없는 지표 사용
- 프로토타입의 예상 효과를 이미 달성한 사회적 성과처럼 과장
- 포용성·공정성을 공식 가산 항목처럼 주장
- 실데이터 접근을 확인하지 않고 아키텍처부터 확정

편의성도 공공가치가 될 수 있다. 예를 들어 고령 주민의 행정 접근 시간을 줄인다면 편의성이 접근성이라는 공공 결과로 연결된다. 핵심은 **누구의 편의가 어떤 지역 변화를 만드는지**다.

## 7. 3일 운영 순서

### Day 1 오전 — 주제 후보와 데이터 확인

- 후보 3~5개의 직접 사용자·최종 수혜자·수요·데이터·지표 작성
- 데이터 API 또는 파일 접근을 실제로 1회 이상 성공
- 공식 게이트 미충족 후보 제외

### Day 1 오후 — 증거사슬과 설계

- 공공가치 증거사슬을 먼저 완성
- 이후 핵심 기능과 아키텍처 결정
- 근거가 추정에 치우친 후보는 보류하거나 축소

### Day 2 — 실데이터 프로토타입

- `데이터 → 판단 → 행동` 한 경로를 끝까지 구현
- 비개발자가 핵심 과업을 수행할 수 있는지 확인

### Day 3 — 효과 측정과 데모

- 영향 지표, 기준선, 측정 주체·방법 작성
- 실제 성과와 예상 효과를 분리
- README 또는 배포 링크로 재현 가능한 데모 준비

### 범위 축소 신호

- Day 1 종료 시 데이터 접근이 성공하지 않음
- Day 2 종료 시 실데이터 기반 핵심 경로가 작동하지 않음

이 경우 기능 추가를 멈추고 데이터셋·사용자·과업 범위를 축소한다.

## 8. 사실·해석·미확정

### 사실

- 평가 항목은 Public Value & Applicability 35%다.
- 공식 설명은 실제 공공 수요와 측정 가능한 지역 영향의 잠재력이다.
- 공공데이터 최소 1개 사용이 필수다.
- 데이터 없는 UI 목업과 원본 데이터 무가공 노출을 지양한다.

### 해석

- Ready to Run과 실제 데이터 통합은 적용 가능성을 설득하는 보조 증거다.
- 공공가치는 데이터, AI, 출력이 아니라 그것이 만드는 판단·행동·지역 상태의 변화에서 발생한다.
- 일반 공공가치 이론은 공식 배점이 아니라 자기점검 렌즈로 사용한다.

### 미확정

- Prototype Bonus 10%가 기본 100%에 추가되는 정확한 방식
- Public Value와 Applicability 내부의 세부 배점
- Microsoft·Azure 기술 사용 의무 또는 가산점
- 우수 프로젝트의 경상북도 저장소 이관 조건과 책임
- 최종 제출 형식과 데모 요구 수준
