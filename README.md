### 위키 구조와 이유

이 팀은 조사 자료를 모으는 걸로 끝내지 않고, 모인 자료를 그대로 최종 피칭 뼈대로 쓰려고 합니다. 그래서 위키 사이드바를 해커톤 피칭이 실제로 심사받는 순서 — **문제 → 해결 → 검증 → 임팩트** — 그대로 따르게 만들었습니다. 이 순서대로 자료가 쌓이면, 발표 직전엔 그 문서들을 훑기만 해도 피칭 스크립트가 나옵니다.

특히 "검증"과 "임팩트"에 힘을 준 이유가 있습니다. 해커톤 피칭에서는 "무엇을 만들었나"보다 "무슨 문제를 풀고, 그게 됐다는 걸 어떻게 증명하며, 그게 누구에게 어떤 가치였는가"가 심사를 가릅니다. 승부는 앞쪽(문제·해결)이 아니라 뒤쪽 두 박자(검증·임팩트)에서 납니다.

**카테고리별로 뭘 채우면 되는가**

| 카테고리 | 페이지 | 채우는 내용 |
| --- | --- | --- |
| 📋 개요 | Home | 팀 소개, 위키를 어떻게 쓰는지 |
| 🎯 문제 (Problem) | 문제 정의 | 우리가 풀려는 문제, 그게 왜 문제인지 근거 — 감이 아니라 데이터로 |
| 💡 해결 (Solution) | 해결 방안 | 고른 기술/구조와 그 이유, **버린 선택지**도 함께 |
| ✅ 검증 (Proof) | 검증 | 측정 지표, 테스트·벤치마크 결과 (Before → After) |
| 🚀 임팩트 (Impact) | 임팩트 | 아래 "임팩트란 무엇인가" 참고 |
| 🔍 조사 자료 | 조사 자료 | 산업 동향, 경쟁 서비스, 레퍼런스 |
| 🎤 피칭 준비 | 피칭 준비 | 위 문서들을 종합한 최종 피칭 스크립트/슬라이드 구성 |

**임팩트(Impact)란**

"임팩트"는 단순히 "많이 좋아졌다"가 아니라, 누구에게 어떤 가치였는지를 구체적으로 보여주는 것입니다.

- **정량화**: "빨라졌다"가 아니라 "작업 시간 6배 단축"처럼 측정 가능한 숫자로
- **구체적 사용자**: "많은 사람이 씁니다"가 아니라 "이런 사람이 이렇게 씁니다"처럼 얼굴이 그려지게
- **실제 반응·증거**: 납품·계약·사용자 피드백처럼 외부에서 인정한 흔적

추상적인 "혁신"보다 구체적인 "6배"가, 막연한 "많은 사람"보다 한 명의 진짜 사용자가 심사위원을 움직입니다.

### 새 자료 추가하기

스킬 다운로드 하기 : https://gist.github.com/eunseo-com/5db07681ec25f6d8909d6e1c1fec0aec -> 링크 복붙해서 ai 에게 준 뒤 스킬로 만들어달라고 하면 됩니다.

위키에 새 자료를 넣을 때는 이 저장소의 [`wiki-organize.md`](./wiki-organize.md) Claude Code 스킬을 씁니다. AI에게 마크다운 파일이나 노션 페이지 URL을 주고 `/wiki-organize`를 실행하면, 알맞은 카테고리를 찾아 위키 페이지로 만들어주고 사이드바까지 자동으로 정리해줍니다.

**예시**

노션 페이지를 위키로 가져올 때:
```
/wiki-organize https://www.notion.so/우리팀/킥오프-회의록-abc123
```

문서를 바로 붙여넣을 때:
```
/wiki-organize
(여기에 회의록이나 조사 자료 텍스트를 그대로 붙여넣기)
```

위키 구조를 다시 정리하고 싶을 때는 인자 없이 그냥 `/wiki-organize`만 실행하면 됩니다.
