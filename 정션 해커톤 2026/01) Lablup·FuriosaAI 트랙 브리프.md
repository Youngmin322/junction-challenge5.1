# 최고의 에이전트 스쿼드 구축

## 배경

최첨단 대형 모델과 대규모 인프라에 누구나 접근할 수 있는 것은 아니다. Lablup과 FuriosaAI는 로컬 또는 손에 쥘 수 있는 규모의 모델과 NPU 기반 환경에서 어느 수준까지 문제를 해결할 수 있는지를 질문한다.

핵심 질문:

> 손에 쥘 수 있는 모델로 어디까지 해낼 수 있을까?

## 결과물

Lablup 제공 PDF Slide 87은 다음 두 결과물을 제시한다.

1. 문제 해결형 AI 에이전트 스쿼드
2. 스쿼드의 문제 해결 과정을 보여주는 인터랙티브 시각화

자동 전사 원문은 시각화를 “recommend”라고 표현하지만, PDF가 두 번째 결과물로 명시하고 시각화에 30점을 배정한다. 따라서 **구현 계획에서는 필수 결과물로 취급**하고, 현장에서는 제출 형식만 재확인한다.

## 스쿼드 설계 범위

- 수학·코딩을 포함하되 이에 한정되지 않는 여러 범주의 문제 대응
- 어떤 에이전트가 작성·수정·검증을 담당할지 결정
- 재시도 조건과 포기·중단 조건 설계
- 에이전트마다 제공 모델 중 하나를 선택
- 에이전트별 도구와 역할 구성
- 에이전트 간 통신·합의·검증 과정 설계
- 핵심 과정은 AI:GO의 에이전트 스쿼드 기능을 기반으로 구현

## 현재 확인된 평가 요소

총점은 100점이다.

| 항목 | 배점 |
| --- | ---: |
| 벤치마크 성능 | 40점 |
| 인터랙티브 시각화 | 30점 |
| 토큰 효율성 | 30점 |

### 벤치마크 성능

- 주최 측 플랫폼에서 자동 채점
- 수학·코딩 등 여러 문제 범주를 다루는 것으로 설명
- 스쿼드가 특정 예제에만 맞춰지지 않고 어느 정도 일반적이어야 한다고 발표에서 언급

### 인터랙티브 시각화

- 에이전트가 어떻게 통신하는지
- 어떤 에이전트가 작업 중인지
- 몇 개의 에이전트가 한 문제에 참여하는지
- 문제 해결 과정과 상태가 어떻게 변화하는지
- Trace 로그를 observability, interpretability, traceability, explainability, clarity, insightfulness 관점에서 표현

### 토큰 효율성

- 정식 검증 제출은 사용량 전부가 토큰 효율성 산정에 반영
- AI:GO 테스트 실행은 전체 비용의 5분의 1만 반영
- 비슷한 벤치마크 성능이라면 적은 토큰으로 달성한 팀이 유리
- Submission Dashboard에서 총 사용량 확인
- 실행별 최종 점수와 모델별 토큰 수 확인
- 제출 결과는 실시간 리더보드에 표시
- 모델별 기준 단가를 적용한 정규화 비용이 낮을수록 유리
- 복수 제출은 가능하지만 테스트와 정식 제출 비용이 모두 누적

## 제출 방식

- 제출 포털: `https://submission.jxc.events.lablup.ai:8444`
- Squad Template JSON 1개와 트랙별 one-shot prompt 1개 제출
- 템플릿 Checking은 무료이며 반복 횟수 제한 없음
- 팀당 동시에 실행할 수 있는 평가는 1개, 대기 제출은 최대 3개
- JSON의 정확한 스키마와 시각화 제출 방식은 아직 미확정

## “미공개 문제” 표현 정정

“미공개 문제”는 발표나 이미지에 명시된 공식 표현이 아니다. 현재 근거로 확정할 수 있는 표현은 다음과 같다.

> 주최 측이 제공하는 여러 범주의 자동 채점형 벤치마크 문제

평가 문항이 사전에 숨겨지는지, 실행마다 달라지는지, 비공개 테스트 케이스가 있는지는 확인되지 않았다.

## 아직 결정하지 않는 것

- 구체적인 사용자 문제 또는 서비스 주제
- 최종 에이전트 수와 역할 구성
- 모델별 배치 전략
- 시각화 기술 스택
- 토큰 절약 전략의 구체적 구현

위 항목은 현장 설명, 실제 AI:GO 기능, 벤치마크 예시와 배점을 확인한 뒤 결정한다.
