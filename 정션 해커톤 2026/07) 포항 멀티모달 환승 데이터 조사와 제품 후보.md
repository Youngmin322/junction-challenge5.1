# 포항 멀티모달 환승 데이터 조사와 제품 후보

> [!summary] 결론
> `실시간 버스 + 자전거/보행 + 공영주차/P+R` 경로는 공개데이터로 3일 MVP가 가능하다. 다만 경북의 **부름콜은 일반 시민용 DRT가 아니라 교통약자 특별교통수단**이며, 포항 일반 DRT의 예약·배차·차량위치 공개 API는 찾지 못했다. 따라서 일반 사용자에게 부름콜을 추천하면 안 되고, 일반 멀티모달 경로와 자격 기반 동행콜 경로를 분리해야 한다.

> [!important] 제품 방향
> 단순히 네이버지도 같은 길찾기를 다시 만드는 것보다, `버스만으로는 오래 걸리거나 환승이 자주 실패하는 구간`을 찾아 자전거·대체정류소·P+R로 우회시키고, 익명 실패 수요를 포항시의 노선·DRT·자전거 연결망 개선 근거로 되돌려주는 제품이 공공가치가 더 강하다.

> [!warning] 검증 상태
> 포항시 노선 파일과 DRT 등록대수 파일은 실제 다운로드·샘플을 확인했다. TAGO·포항시 실시간 API는 endpoint 도달까지 확인했으나 등록된 ServiceKey가 없어 라이브 포항 행을 받지 못했다. `cityCode=37010`, 정류소별 이용자 데이터의 실제 집계주기, 동행콜 실시간 포항 행은 키 발급 후 재검증해야 한다.

## 1. 출발 문제와 조사 질문

지역 주민 의견은 “포항 버스 노선이 불편하고, 버스와 걷기만 조합한 경로로는 실제 이동 선택지가 부족하다”는 것이다.

조사 질문:

1. 포항 버스 노선·정류소·실시간 위치·도착 데이터를 경로 그래프로 만들 수 있는가?
2. 포항 자전거도로를 버스의 첫·마지막 구간에 연결할 수 있는가?
3. 부름콜과 일반 DRT를 어떤 이용자에게 어떤 조건으로 연결할 수 있는가?
4. 택시·주차·공유 PM·철도·시외버스까지 확장 가능한가?
5. 최적 경로 추천뿐 아니라 포항시의 교통 공백 개선으로 이어질 데이터가 있는가?

## 2. 가장 중요한 용어 교정

### 경북 부름콜

[경북 광역이동지원센터 부름콜](https://brmcall.co.kr/info01)은 「교통약자의 이동편의 증진법」과 경상북도 조례에 따라 대중교통 이용이 어려운 중증장애인 등에게 이동편의를 제공하는 특별교통수단이다.

- 일반 주민 대상 DRT가 아님
- 이용 자격, 예약 조건, 이동 가능 지역과 요금 제약이 있음
- 일반 경로탐색 결과에 무조건 노출하면 안 됨
- 자격을 확인한 접근성 모드에서만 후보가 될 수 있음

### 일반 수요응답형 교통 DRT

- 이용자의 호출이나 예약에 따라 운행 경로·시간을 탄력적으로 정하는 버스·택시형 서비스
- 한국교통안전공단 DRT지원시스템 참여 통계상 포항에 택시형 4대가 등록되어 있음
- 그러나 현재 운영지역, 이용자격, 운행시간, 승하차 지점, 실시간 차량 가용성과 예약·배차 API는 공개데이터에서 확인하지 못함

### 포항 동행콜

공개 표준데이터에서 확인되는 포항의 교통약자 이동지원 서비스는 `동행콜`이다.

- 차량: 33대
- 대표전화: 1800-9300
- 운행지역: 포항시 및 조건에 따른 경북·대구 이동
- 예약: 최대 5일 전으로 표준데이터에 기록
- 이용자격: 대중교통 이용이 어려운 교통약자

운영시간과 자격은 변할 수 있으므로 실제 서비스 연결 전 공식 센터에 재확인해야 한다.

## 3. 경북에 DRT 정보가 많다는 가설

- 데이터: [한국교통안전공단 DRT 등록대수 현황](https://www.data.go.kr/data/15064502/fileData.do)
- 기준: 2025-12-31, 포털 수정 2026-08-20
- 경북: 14개 참여 시군, 택시형 2,262대, 버스형 6대
- 포항: 택시형 4대, 버스형 0대

판정:

- `DRT지원시스템 참여 시군 수` 기준으로 경북은 경남 15개 다음인 14개라 관련 정보가 많은 편이라는 가설은 지지된다.
- 하지만 2,262대를 모두 앱 기반 자동배차 DRT로 해석하면 안 된다.
- 플랫폼형 DRT와 지자체 독자 시스템이 통계에서 빠질 수 있고, 반대로 택시형 등록이 일반 시민이 즉시 호출 가능한 서비스를 뜻하지 않을 수 있다.
- 이 데이터는 지역별 운영 기반 규모를 보여주는 정적 기준선이지 경로탐색 API가 아니다.

## 5. 버스 데이터 상세

### 5.1 포항시 시내버스 노선정보

- 데이터: [3034960](https://www.data.go.kr/data/3034960/fileData.do)
- 기준: 2026-05-12
- 규모: 10,005행
- 갱신: 연간
- 형식: CSV와 공공데이터포털 자동변환 JSON/XML
- 이용조건: 무료, 제한 없음

필드:

- 노선명·노선상세
- 기점·종점·회차지
- 승강장 개수
- 노선거리·총 운행시간
- 승강장 순번·상하행·승강장명·승강장거리
- 데이터 기준일

실제 샘플:

- 110번
- 송도해수욕장회차지 포함
- 승강장 53개
- 노선거리 21,690m
- 운행시간 60분

강점:

- 승강장 순번이 있어 노선 방향의 그래프 간선을 만들 수 있다.
- 포항시가 직접 제공한 2026년 기준 파일이다.

한계:

- 정류소 좌표와 TAGO 표준 `nodeId`가 없다.
- 첫차·막차·요일별 시간표와 개별 운행 회차가 충분하지 않다.
- 노선명·승강장명만으로 TAGO와 조인하면 동명이소·띄어쓰기·상하행 오류가 생긴다.
- GTFS가 아니다.

포항 도시코드는 `37010`으로 확인됐지만 활용신청 후 공식 `getCtyCodeList` 응답으로 다시 고정해야 한다.

### 5.3 TAGO 실시간 도착정보

- 데이터: [15098530](https://www.data.go.kr/data/15098530/openapi.do)
- endpoint: `https://apis.data.go.kr/1613000/ArvlInfoInqireService/getSttnAcctoArvlPrearngeInfoList`
- 입력: `cityCode`, `nodeId`
- 출력: `routeid`, `routeno`, `routetp`, `arrprevstationcnt`, `arrtime`, `vehicletp`
- 승인: 개발·운영 자동
- 트래픽: 개발 10,000회/일
- 이용조건: 무료, 제한 없음

제품 활용:

- 현재 정류소까지 걷거나 자전거로 도착하기 전에 버스를 놓칠 확률 계산
- 다음 정류장으로 이동하면 더 빨리 탈 수 있는지 비교
- 환승 버스의 ETA와 현재 버스의 예상 도착을 함께 비교
- 저상버스 필요 사용자에게 차량유형을 반영

주의:

- API가 과거 도착 이력을 제공하지 않으므로 30~60초 폴링 결과와 `observed_at`을 직접 저장해야 한다.
- `arrtime`은 초 단위 예측이지 실제 도착시각이 아니다.

### 5.4 포항 정류장별 이용자 추이

- 데이터: [15139516](https://www.data.go.kr/data/15139516/openapi.do)
- endpoint: `https://apis.data.go.kr/5020000/busStopAcctoUserTrnsitnStepTwo/getBusStopAcctoUserTrnsitnStepTwo`
- 형식: REST JSON
- 트래픽: 개발 10,000회, 개발 자동·운영 심의
- 핵심 필드: 정류소, 위경도, 노선, 시간대별 승객수

가능한 활용:

- 환승 실패가 많은 정류소·시간대의 수요 가중치
- 버스 공백 구간에서 자전거 피더나 DRT 후보권역 선정
- 이용자 수가 많은데 실시간 도착 편차가 큰 정류소 우선 개선

포털의 “실시간” 표기만으로 실제 승객수가 분 단위 갱신된다고 단정하면 안 된다. 관측일·집계기간 필드를 라이브 샘플에서 확인해야 한다.

## 6. 자전거·보행 데이터 상세

### 6.1 전국자전거도로표준데이터

- 데이터: [15100063](https://www.data.go.kr/data/15100063/standard.do)
- endpoint: `https://api.data.go.kr/openapi/tn_pubr_public_bike_road_api`
- 입력 필터: `ctpvNm=경상북도`, `sggNm=포항시`
- 승인: 개발·운영 자동, 개발 10,000회
- 갱신: 연간

필드:

- 노선명·노선번호
- 기점·종점 주소와 위경도
- 주요 경유지
- 총길이, 일반도로·자전거도로 폭
- 자전거도로 종류와 고시 여부
- 관리기관·기준일

가장 큰 한계:

- 실제 굴곡을 가진 선형 geometry가 아니라 기점·종점·주요 경유지 중심이다.
- 교차로 연결, 끊긴 구간, 역주행 가능 여부, 공사·노면상태, 경사, 조명, 사고 위험을 제공하지 않는다.
- 안전한 턴바이턴 자전거 경로에 단독 사용하면 안 된다.

### 6.2 도로중심선과 보행자전용도로

[VWorld 도로중심선 WFS](https://www.data.go.kr/data/15056842/openapi.do)는 포항 bbox의 선형 geometry를 보완할 수 있다. [도시계획정보 보행자전용도로 SHP](https://www.data.go.kr/data/15147477/fileData.do)는 전국 15,876개 도시계획시설을 제공한다.

하지만 둘 다 완전한 보도망이 아니다.

- 도로중심선에는 보행·자전거 통행 허용, 보도 유무, 단차·경사 정보가 부족함
- 보행자전용도로는 법정 도시계획시설만 포함하며 생활도로 전체를 포함하지 않음
- 데모는 직접 검증한 회랑으로 제한하거나 OpenStreetMap 기반 라우팅 엔진을 보조로 사용해야 함

### 6.3 자전거 보관소

- 데이터: [전국자전거보관소표준](https://www.data.go.kr/data/15017318/standard.do)
- 규모: 전국 16,170행
- 갱신: 지자체 취합, 2일 전 기준으로 매일 현행화된다고 설명
- 필드: 명칭, 주소, 위경도, 보관대수, 설치형태, 차양막·공기주입기·수리대 등

자전거 보관소가 실제로 포항 행을 충분히 포함하는지 확인한 뒤 버스 정류장 20~50m 이내의 환승거점으로 사용한다.

## 7. 부름콜·동행콜·DRT 데이터 상세

### 7.1 경상북도 부름콜 접수 데이터

- 데이터: [15128842](https://www.data.go.kr/data/15128842/fileData.do)
- 기준 파일: 2024-06-17
- 규모: 923,158행
- 형식: CSV와 자동변환 JSON/XML
- 갱신: 1회성
- 이용조건: 공공누리 제3유형, 출처표시·변경금지

필드:

- 접수시간
- 목적지
- 장애유형·휠체어 여부
- 출발지·목적지 위경도와 시군구
- 배차시간·승차시간·하차시간
- 배차구분·차량종류

가치:

- 접수→배차→승차→하차의 전체 시간이 있어 대기·주행·공차 이동을 분석할 수 있다.
- 포항 출발·도착 건만 분리해 시간대별 교통약자 OD와 대기시간 기준선을 만들 수 있다.
- 일반 버스·보행으로 접근하기 어려운 목적지와 시간대를 찾는 강한 데이터다.

제약:

- 민감한 장애유형과 위치가 포함되므로 재식별 위험이 있다.
- 원시 OD를 지도에 표시하거나 개인 경로로 저장하지 않는다.
- 최소 격자·시간대 집계, 희소 셀 억제, 장애유형 범주 축소가 필요하다.
- 제3유형 변경금지 조건과 비식별 집계·파생지표 공개 가능 범위를 사전에 확인해야 한다.
- 일반 시민의 DRT 수요를 대표하지 않는다.

### 7.2 전국 교통약자 실시간 현황

- 데이터: [15140825](https://www.data.go.kr/data/15140825/openapi.do)
- 기관: 행정안전부·한국지역정보개발원
- 갱신: 실시간
- 트래픽: 개발 5,000회, 개발·운영 자동
- 입력: `stdgCd`
- 값: 기준시각, 총차량·운행차량·가용차량, 예약·대기 건수

포항 행이 실제 반환되면 `현재 이용 가능한 특별교통수단인가`의 신뢰도에 쓸 수 있다. 경로 예약 자체를 수행하는 API는 아니다.

### 7.3 일반 DRT 공개데이터 공백

한국교통안전공단 [DRT지원시스템](https://drt.kotsa.or.kr/)은 로그인과 개인정보 동의가 필요한 운영 시스템이며 공개 경로 API가 아니다. 이번 조사에서는 포항 일반 DRT의 다음 값을 제공하는 공식 공개 API를 찾지 못했다.

- 운영권역·가상정류장
- 운행시간·요금·이용자격
- 호출·예약 이벤트
- 차량 위치·잔여좌석
- 요청 수락·배차 ETA
- 취소·노쇼·실제 승하차

따라서 MVP에서는 일반 DRT를 다음 중 하나로만 다룬다.

1. 운영기관과 별도 협약해 데이터를 받는다.
2. 정보가 확인된 서비스만 전화·앱 연결 버튼으로 제시한다.
3. DRT가 있으면 좋아질 `후보권역`을 행정용 분석 결과로 제시한다.

가용성이 확인되지 않은 DRT를 확정 경로 구간으로 넣지 않는다.

### 공유 PM·카셰어링

### 철도·시외버스

포항역·시외버스터미널을 장거리 환승 노드로 확장할 수 있다. 다만 3일 MVP에서는 도시 내 버스·자전거·보행·P+R에 집중하고, 철도·시외버스는 2차 범위가 적절하다.

## 9. GTFS와 내부 데이터 모델

이번 조사에서 포항 버스의 정적 GTFS ZIP, GTFS-Realtime protobuf, GTFS-Flex는 확인되지 않았다.

따라서 다음 내부 유사 스키마를 직접 만든다.

| 내부 테이블 | 원천 | 핵심 키 |
| --- | --- | --- |
| `stops` | TAGO 정류소 | `city_code`, `node_id` |
| `routes` | TAGO 노선 + 포항 파일 | `route_id`, `route_no` |
| `route_stops` | 포항 승강장순번 + TAGO 경유정류소 | `route_id`, `direction`, `stop_sequence` |
| `vehicle_positions` | TAGO 버스위치 폴링 | `route_id`, `vehicle_id`, `observed_at` |
| `arrivals` | TAGO 도착 폴링 | `node_id`, `route_id`, `observed_at` |
| `bike_edges` | 자전거도로 + 검증된 도로망 | `edge_id`, geometry, 통행비용 |
| `walk_edges` | 도로중심선·보행도로·보조 라우터 | `edge_id`, geometry, 통행비용 |
| `mobility_hubs` | 정류소·보관소·주차장·택시승강장 | `hub_id`, `mode`, 좌표 |

이를 `공식 GTFS`라고 부르지 않는다. 해커톤 이후 표준화한다면 GTFS 정적 피드와 DRT용 GTFS-Flex 변환 가능성을 검토한다.

## 10. 공간·시간 결합 규칙

### 버스

- `cityCode=37010 + nodeId + routeId`
- 포항 파일의 승강장명은 TAGO 정류소 좌표·상하행·순번과 함께 매칭
- 이름만으로 조인하지 않음

### 자전거·보행·주차

- 모든 좌표를 WGS84로 통일
- 정류소와 자전거 보관소·주차장을 20~50m 이내 스냅
- 자전거도로 표준의 기종점 사이를 직선으로 연결하지 않음
- 검증되지 않은 도로는 안전비용을 높이거나 경로에서 제외

### 동적 데이터

- 원천에 시각이 없어도 모든 수집에 `observed_at_kst` 저장
- 예측 ETA와 실제 관측·도착을 분리
- API 장애·오래된 응답·결측을 경로 신뢰도에 반영

## 11. 경로 최적화 목적함수

최단시간 하나만 최소화하면 자전거·환승의 실용성이 사라진다.

$$
Cost = T + \alpha W + \beta R + \gamma C + \delta A + \epsilon U
$$

| 항목 | 의미 |
| --- | --- |
| $T$ | 예상 총 소요시간 |
| $W$ | 걷기·자전거 이동 부담 |
| $R$ | 환승 실패·지연 위험 |
| $C$ | 요금·주차비·호출비용 |
| $A$ | 접근성 제약 위반 비용 |
| $U$ | 데이터가 오래됐거나 DRT 가용성이 미확인인 불확실성 |

사용자 선택 모드:

- 가장 빠르게
- 가장 적게 걷기
- 자전거+버스
- 자동차 주차+버스
- 휠체어·교통약자 접근성
- 환승 실패 위험 최소화

## 12. 제품 후보 순위

### 1위 — 포항 모드전환 경로 + 교통공백 증거지도

주민에게는 버스·자전거·보행·P+R 대안 경로를 주고, 행정에는 “기존 버스만으로 45분 안에 도달하지 못하는 시간대·지역”을 익명 집계한다.

왜 1위인가:

- 실시간 TAGO와 포항 노선·수요 데이터가 핵심 판단에 직접 쓰임
- 부름콜 공개 API가 없어도 MVP가 성립함
- 주민 편의와 포항시 노선·DRT 정책 개선을 같은 제품에서 연결함
- 단순 길찾기와 달리 경로 실패가 공공서비스 개선 근거로 축적됨

### 2위 — 자격 기반 동행콜 연계 접근성 경로

교통약자 이용자에게 버스 저상차량·보행 부담·동행콜 운영조건과 실시간 가용차량을 함께 보여준다.

조건:

- 자격 확인을 통과한 사용자에게만 노출
- 예약을 보장하지 않고 공식 전화·앱으로 연결
- 장애유형·OD 원시데이터를 저장하지 않음

### 3위 — 자전거 피더 + 버스 환승

긴 도보 대신 자전거로 더 안정적인 정류장이나 자주 오는 노선까지 이동시키는 경로다. 포항 자전거도로의 실제 geometry와 안전성 검증이 가장 큰 선행조건이다.

### 4위 — P+R·택시 환승

외곽에서 자동차나 택시로 환승거점까지 접근한 뒤 버스를 이용한다. 주차 잔여면과 택시 ETA가 확인되지 않으면 “가능한 후보”이지 실시간 보장 경로가 아니다.

### 보류 — 일반 DRT 포함 확정 경로

포항 일반 DRT 운영기관이 예약·배차·차량위치 또는 최소한 실시간 가용성 데이터를 제공할 때만 활성화한다.

## 14. 3일 MVP

### Day 1 — 그래프와 생존성

1. 포항 노선파일을 내부 `routes`, `route_stops`로 변환
2. TAGO `cityCode=37010`과 포항 정류소·노선 반환 확인
3. 포항 노선 승강장과 TAGO `nodeId` 매핑률 측정
4. 포항 자전거도로·도로중심선·보관소·공영주차장 수집
5. 포항 중심 회랑 1~2개만 직접 검증

### Day 2 — 동적 경로

- TAGO 도착·차량위치를 30~60초 폴링
- 걷기→버스, 자전거→버스, 주차→버스 후보 생성
- `총시간 + 환승 실패 위험 + 보행/자전거 부담 + 데이터 불확실성`으로 순위화

### Day 3 — 비교와 공공가치

- 최단시간, 적게 걷기, 자전거+버스, P+R 대안 비교
- ETA 신선도와 데이터 공백 배지 표시
- 익명 “경로 없음·환승 실패” 이벤트를 행정용 취약구간으로 집계
- 동행콜은 자격 확인 모드와 공식 접수 연결만 구현

- [ ] 정류장별 이용자 추이에 관측일·시간대·승객수가 실제로 존재하는가?
- [ ] 전국자전거도로에 포항 행이 몇 개이며 좌표 결측률은 얼마인가?
- [ ] 도로중심선과 자전거도로로 검증 회랑의 연속된 geometry를 만들 수 있는가?
- [ ] 포항 자전거보관소와 공영주차장 좌표가 충분한가?
- [ ] 교통약자 실시간 API가 포항 총·가용차량과 대기건수를 반환하는가?
- [ ] 일반 DRT 운영기관이 현재 포항 서비스 범위와 연결 방법을 확인해 주는가?
- [ ] 포항 공개 데이터의 GTFS 또는 더 상세한 운행시간표가 별도로 존재하는가?

> [!danger] 중단 조건
> TAGO가 포항 실시간 도착·차량위치를 반환하지 않거나, 포항 파일과 정류소 ID 매핑이 낮으면 “실시간 최적경로” 주장을 중단한다. 이 경우 포항 노선·정류장 수요를 이용한 `교통공백 분석과 자전거·DRT 후보권역 제안`으로 축소한다.

## 16. 개인정보·안전·라이선스

- 부름콜 접수 데이터의 장애유형·좌표·시각 조합은 재식별 위험이 높다.
- 개인 이동이력은 저장하지 않고 격자·행정동·시간대별로 집계한다.
- 소수 OD 셀은 억제하거나 상위 행정구역으로 병합한다.
- 부름콜 접수 데이터는 제3유형 변경금지이므로 파생 공개 범위를 기관에 확인한다.
- 자전거 안전성 데이터가 부족하므로 검증하지 않은 구간을 “안전한 길”이라고 표현하지 않는다.
- 동행콜 자격·예약·도착을 앱이 보장한다고 표현하지 않는다.

## 17. 사실·해석·미확정

### 확인된 사실

- 포항시 2026-05-12 시내버스 노선파일은 10,005행이며 승강장 순번을 포함한다.
- TAGO는 노선·정류소·도착·위치 API를 제공하며 도착 API는 개발 10,000회·자동승인이다.
- 전국자전거도로표준은 기종점 좌표·경유지·길이·폭·도로종류를 제공한다.
- 경북 부름콜은 교통약자 특별교통수단이다.
- 부름콜 접수 파일은 923,158행이며 접수·배차·승하차시각과 OD 좌표가 있다.
- TS DRT 등록대수 자료에서 포항은 택시형 4대, 버스형 0대다.
- 이번 조사에서 포항 GTFS·GTFS-RT·GTFS-Flex는 확인되지 않았다.

### 근거 기반 해석

- 공개데이터만으로 일반 시민용 DRT를 확정 경로에 넣을 수 없다.
- 자전거도로 표준은 경로 안전성을 판정하기보다 연결 후보를 찾는 데이터다.
- 주민용 경로 추천과 익명 교통공백 행정 분석을 결합해야 기존 지도 서비스와 차별화된다.

### 미확정

- TAGO 포항 실시간 4종의 실제 반환률과 지연
- 포항 정류장 수요 API의 집계주기와 결측
- 포항 자전거도로 geometry·연속성·안전성
- 일반 DRT의 현재 운영명·권역·접수채널·가용성
- 동행콜 실시간 API의 포항 행 제공 여부
- 포항시가 별도로 보유한 GTFS·운행시간표·교통카드 OD 제공 가능성
