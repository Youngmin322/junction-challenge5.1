# CBL Engage 세션 01

> [!summary] 현재 판정
> 수정된 Codex-Claude 협업 프로토콜로 CBL 루프를 진행할 수 있다. 현재 단계는 **Engage — Iterate**다. 트랙과 공식 제약은 확인됐지만 팀이 소유하는 Big Idea, Essential Question, Challenge, 학습 목표가 아직 확정되지 않았다.

> [!success] 상호 검증 결과
> Claude가 Evidence Ledger와 수정된 협업 규칙을 원문에 대조했다. 1차 조건부 승인에서 발견된 P1 2건과 P2 4건을 보완한 뒤, 변경분 재검토에서 **인용 11/11 확인, 새 모순 0건, 조건 없는 승인**을 받았다. `Engage — Iterate` 판정은 유지한다.

## 1. 세션과 협업 프로토콜

- Codex 세션: `01a024aa-4792-7312-88f3-97be671eda2d`
- Claude 세션: `150d43c2-c244-4972-8cf4-39a9623ba9c4`
- 원문: `Codex-Claude 협업 프로토콜` v1.0
- 양측 판정: **조건부 수용, Engage 진입 가능**

### 그대로 유지

1. 모델 간 합의를 증거로 사용하지 않는다.
2. 근거·해석·가정·미확인을 분리한다.
3. 한 번에 한 주체만 프로젝트 파일을 수정한다.
4. 이견은 다수결로 없애지 않고 양측 근거와 선택지를 사용자에게 전달한다.

### 이번 CBL 세션에서 조정

1. 사용자는 Big Idea, Essential Question, Challenge, `Go / Iterate / Stop`의 최종 결정자다.
2. Codex는 조사·Evidence Ledger·프로젝트 파일 반영을 맡고, Claude는 사실 검증과 대안·계획 초안을 맡는다. Claude의 초안은 사용자 결정을 대체하지 않는다.
3. 단계 게이트는 `I2 / C2`, 일상 검토는 `I1 / C1`로 분류한다. 파일·도구·토큰 상한은 적용하지 않고 실제 사용량만 기록한다.
4. Challenge 6 헬스케어 전용 조항은 적용하지 않는다. 개인정보, 기관 명의, 외부 발송·배포, 공공데이터 라이선스·재배포 조건, 팀원 실명 노출은 `I3` 안전 게이트로 다룬다.
5. 되돌아갈 때 전체를 재탐색하지 않고 이전 판정표와 변경분, 되돌아간 원인만 검토한다.
6. 프로젝트 기록과 공개 자료 Evidence Ledger는 Codex가 작성하고 Claude가 검증한다. 인터뷰·관찰 증거 카드와 개인 성찰은 러너가 직접 작성한다.
7. Investigate가 끝나기 전의 앱·AI·Azure·API·기능 언급은 모두 `[가설]`로 표시한다.

## 4. 사실·가설·미지·제약

### 확인된 사실

- 공공데이터 최소 1개를 실제 기능에 사용해야 한다.
- 경상북도의 실제 문제를 다뤄야 한다.
- 서비스형, 데이터 인프라형 또는 결합형이 가능하다.
- 데이터 인프라형은 GitHub 공개와 오픈소스 라이선스 명시가 필수다.
- 단순 UI 목업과 원본 데이터 단순 노출은 부족하다.
- 팀은 4명이며 역할이 기획·디자인·개발로 나뉘어 있다.

### `[가설]` 또는 보류 아이디어

- `[가설]` AI가 반드시 필요한 판단·행동 지점이 존재할 것이다.
- `[가설]` 서비스형이 짧은 해커톤에서 공공가치를 보여 주기 더 쉬울 수 있다.
- `[가설]` 데이터 인프라와 작은 사용 사례를 결합하면 평가 사슬을 설명하기 쉬울 수 있다.
- `[가설]` Microsoft·Azure 사용이 필요하거나 유리할 수 있다.

### 미지

- 팀원 각자가 중요하다고 느끼는 경상북도 맥락과 Big Idea는 무엇인가?
- 어떤 직접 사용자와 최종 수혜자를 팀이 실제로 이해하거나 접할 수 있는가?
- 어떤 지역 문제의 규모·빈도·심각성을 신뢰할 근거로 확인할 수 있는가?
- 문제를 설명하거나 행동을 바꾸는 데 사용할 수 있는 데이터는 무엇이며 실제 접근 가능한가?
- 기존 대안은 무엇이며 어느 조건에서 실패하는가?
- 제출 형식·마감·Azure 사용·전국 데이터 인정·라이선스·이관 조건은 무엇인가?
- 서비스형에도 GitHub 공개 의무가 있는가?
- 프로토타입 보너스 10%는 총점에 어떻게 합산되는가?

### 현재 제약

- 해커톤 기간이 짧아 Challenge를 좁혀야 한다.
- 실제 데이터 접근 성공 여부를 조기에 확인해야 한다.
- 개인정보·민감정보를 수집하지 않는 공개 자료 조사부터 시작한다.
- 데이터 라이선스·재배포·출처 표시 조건을 확인하기 전 외부 배포하지 않는다.
- 팀 코어타임·이해관계자 접근 가능성·해커톤 이후 유지 주체는 아직 확인되지 않았다.

## 6. 다음 팀 활동 — 러너가 직접 작성

팀원 각자가 다른 답을 보지 않고 먼저 작성한다. 진행자는 개인 발산이 끝날 때까지 위 `[가설]` 목록과 기존 해결안 아이디어를 공유하지 않는다.

1. 경상북도 또는 지역 공동체에서 내가 중요하다고 느끼는 변화 3개는 무엇인가?
2. 각 변화가 나에게 중요한 구체적 경험·이유는 무엇인가?
3. 그 변화와 관련해 `누가, 언제, 어디서, 무엇 때문에` 어려움을 겪는다고 생각하는가?
4. 내가 이미 선호하는 `[가설] 해결안`은 무엇이며, 그것이 질문을 좁힐 위험은 무엇인가?
5. 이번 해커톤에서 배우고 싶은 도메인 지식 1개와 역량 1개는 무엇인가?
6. 어떤 증거가 나오면 이 문제 방향을 중단하거나 바꿀 것인가?

각자 작성 후 다음 통합 산출물을 만든다.

- Big Idea 후보 3개
- 해결안 단어가 없는 Essential Question 후보 5개
- 직접 사용자·최종 수혜자·기존 대안이 다른 문제 방향 3개
- 팀 운영 합의: 코어타임, 결정 방식, 기록 책임자, 미완료·갈등 복구 규칙

| 미확인                 | 사용자·문제·데이터·마감·제출·라이선스·이관 조건                                                                            |
| 이 검토가 바꾸는 결정        | 제품 후보 선택 전에 팀의 의미·질문·Challenge를 먼저 작성                                                                  |
| 다음 결정               | 팀 자작 답변을 통합해 Big Idea와 Essential Question 후보를 선택할지 판단                                                  |
| Go / Iterate / Stop | Iterate                                                                                                |
| 실제 사용량              | 예산·파일·도구·토큰 상한 없음. 구독 세션에서 정확한 토큰·비용 수치가 노출되지 않아 추정값은 기록하지 않음. Claude 검증 응답 생성 시간은 CLI 표시 기준 약 3분 40초. |
