# 해파리 기존 전제 반증과 대체 문제공간

> [!abstract] Kill-the-Leader 방법
> 현재까지 눈에 띈 후보를 없애야 한다고 가정하고, 실패 원인을 먼저 쓴 뒤 같은 자산으로 갈 수 있는 다른 문제공간을 연다. 탈락 판정이나 우선순위는 내리지 않는다.

## 1. 전제 공격표

| 기존 전제 | 가장 강한 반증 | 이 전제가 틀려도 남는 자산 | 열리는 대체 문제공간 |
| --- | --- | --- | --- |
| 공개 데이터로 시설 도착시간을 계산할 수 있다 | 동일 개체 궤적·수직행동·시설 앞 밀도 라벨이 없음 | 흐름모델, 출현 좌표, 해안 세그먼트 | ETA 대신 접근 가능성·현장확인 우선순위 |
| 최신·연속·동일 개체 추적 자료와 충분한 발생 라벨이 없다 | 과거 신고·목시·트롤·주간 출현률은 있으나 이 반증을 해소하지 못함 | 다중 관측 양식 | 라벨 한계를 인정한 능동관측·관측노력·스키마·신선도 문제 |
| 해파리 API로 생물유입 전반을 예측할 수 있다 | 2021 한울 정지는 살파이며 해파리와 예측근거가 없음 | 공통 이벤트·업무흐름 | 종별 플러그인, 교차예측 금지형 운영 OS |
| 원전이 가장 명확한 사용자다 | 상세 시설데이터·SOP·인터뷰가 없고 보안·안전 문턱이 큼 | 인프라 사건 패턴 | 양식·담수화·지자체·연구 능동관측 등 병렬 탐색 |
| 지도와 경보가 제품의 중심이다 | NIFS·시민앱·상용 예보·시설 시스템이 이미 존재 | 데이터 출처와 이벤트 | 검증 태스크, 증거 감사, 상호지원, 사후학습 |
| 더 정확한 모델이 가장 큰 가치다 | 행동 임계값·승인선·오출동 비용이 모름 | 불확실성·모델 충돌 | decision provenance, 훈련·SOP 실험 |
| 해파리 증가는 기후변화가 원인이다 | 체계적 리뷰는 많은 주장이 근거보다 증폭됐음을 지적 | 환경변수 시계열 | 인과 설명 대신 조건부 시나리오·가설 비교 |
| 해파리는 수동 부유체다 | 수직이동·종별 운동성·생존이 존재 | 물리 수송의 기준선 | 관측-모델 잔차로 행동·센서 오류를 분리 |
| 신고가 많으면 위험이 크다 | 관광객·날씨·조사노력 편향 | 신고 메타데이터 | 음성 관측·coverage ledger·능동표본 |
| 한 번의 해커톤 시연으로 예측력을 입증할 수 있다 | 실제 취수구 막힘 라벨과 시간외 검증이 없음 | 재현 가능한 파이프라인 | 데이터 품질·근거추적·모의훈련 성능 시연 |
| 자원화는 피해를 가치로 바꾼다 | 혼합물·염분·독성·오염·물류·수요가 검증 안 됨 | 수거·인계 사건 | 처리 체인오브커스터디·품질검사 시장 탐색 |
| 시민신고를 늘리면 데이터가 좋아진다 | 양성 편향·오인·중복·검증부담이 증가 | 사진·위치·시간 | 검증자 배정·음성 샘플·표본설계 게임화 |

## 2. 프리모텀: 72시간 뒤 실패했다고 가정

| 실패 장면 | 조기 신호 | 지금 열어둘 회피 실험 |
| --- | --- | --- |
| “그냥 또 하나의 해파리 지도”라는 평가 | 화면 설명이 점·색상에서 끝남 | 한 사건의 관측→검토→승인→확인→종료 상태전이를 시연 |
| 원전 사례가 사실오류로 무너짐 | 2021 정지를 해파리로 표기 | 사건별 생물종·출처·신뢰도 카드와 살파 정정 전면 표시 |
| AI가 실제로 한 일이 불분명 | 단순 API 표시 | 모델 충돌·불확실성이 큰 구간의 확인 태스크 생성 또는 근거 추출 시연 |
| 예측 정확도를 질문받고 답하지 못함 | ETA·정확도 수치가 검증 없이 등장 | 측정 가능한 데이터 품질·시간분할 공간 적중·업무처리 지표로 한정 |
| 운영자가 왜 필요한지 증명 못함 | 사용자 발화·현재 workflow 0건 | 사용자 검증 전용 가설 라벨과 인터뷰 스크립트 공개 |
| 범용 OS가 공허해짐 | 해파리 외 슬롯에 데이터가 없음 | 실제 구현은 해파리 모듈 하나, 나머지는 확장계약만 표시 |
| 시민과학이 저품질 신고로 붕괴 | 종 불명·중복·인기해변 편중 | 음성 관측, 검증대기 큐, 관측노력 점수 포함 |
| 고위험 시설 자동화로 보임 | “자동 정지·자동 출동” 문구 | 모의 요청·사람 승인·근거 카드만 구현 |
| 데이터 호출이 데모 당일 실패 | API 키·호출량·스키마 미검증 | 캐시된 공개 샘플과 출처·시각 표시, 실패상태 UI |
| 원거리 아이디어가 은유놀이로 보임 | 도메인 근거 없이 이름만 붙음 | 구조적 유추/은유/실제 연결을 분리 표기 |

## 3. 대체 문제공간 씨앗 30개

모두 같은 지위로 둔다.

1. 관측 공백을 줄이는 능동 샘플링 큐
2. 해양모델 간 불일치 지도와 조사선 배정
3. 공식보고 유효시간·데이터 신선도 레지스트리
4. 생물종 오인 방지 사건 팩트체커
5. 원전·양식·담수화가 공유하는 marine-event 스키마
6. 시설별 비공개 임계값을 노출하지 않는 로컬 규칙엔진
7. 경보 승인·해제의 근거 감사로그
8. 신고 사진 검증자와 전문가를 매칭하는 대기열
9. 양성·음성 관측을 균형 있게 모으는 시민과학 미션
10. 조사비용 대비 정보이득을 비교하는 표본설계 시뮬레이터
11. 과거 사건을 재생해 SOP를 시험하는 훈련실
12. 해양생물 유입 자원·인력의 상호지원 교환소
13. 스크린 차압·세척 이력에서 정비창을 찾는 내부용 모듈
14. 수거물의 검사·운반·처리를 추적하는 폐기물 패스포트
15. 해파리 출몰과 어획·가격 변동의 관계를 반증하는 연구도구
16. 해류모델과 생물 관측 잔차를 해양센서 QA에 쓰는 도구
17. 불확실한 공공 위험문구의 버전·승인 관리
18. 지역주민에게 사건 근거와 조치 상태만 공개하는 투명성 레이어
19. 보험용 예방행동 증빙·사건 타임라인
20. 시설 공급망의 망·필터·선박 리드타임 시뮬레이터
21. 여러 종의 서로 다른 인과모델을 섞지 않는 causal firewall
22. 데이터 결측·지연 자체를 운영사건으로 올리는 품질 경보
23. 연구 실패·음성 결과를 검색 가능한 반증 저장소
24. 해파리라는 생물 센티널로 연안 관측망의 사각을 찾는 데이터 제품
25. 살파를 독립 대상으로 두고 관측·발생·수송·시설영향 데이터부터 조사하는 별도 트랙
26. 해파리보다 경북 피해근거가 큰 적조·고수온이 있는지 비교하는 문제 적합성 감사
27. 추가 소프트웨어 없이 현 물리설비·전화망·절차로 충분한지를 입증하는 `do-nothing baseline`
28. 사건 후 정산·감사·보험·주민설명만 다루는 post-event 전용 문제공간
29. 해파리와 분리해 연안 관측 공백 자체를 주제로 삼는 coverage commons
30. NIFS 내부 도구가 이미 충분하다는 가설을 검증하는 대체재 감사

## 4. 중단으로 이어질 수 있는 조건

반증을 무조건 새 기능으로 흡수하지 않는다. 아래가 확인되면 해당 문제공간을 멈출 이유가 된다.

- 경북에서 대상 종의 노출·피해가 작고 더 큰 공공문제가 따로 있음
- 현행 NIFS·시설 계측·물리 차단·전화망으로 최근 사건의 결정 지연이 충분히 해결됨
- 필요한 시설영향 라벨을 안전·보안·비용 제약상 얻을 수 없음
- 새 소프트웨어의 개입지점보다 망·스크린·취수설계 같은 물리 대안이 비용효과를 지배함
- 모델 오탐·미탐 비용을 감당하거나 책임질 실제 주체가 없음

팀이 이 조건을 판단하기 전에는 어느 후보도 자동으로 생존하거나 탈락하지 않는다.
