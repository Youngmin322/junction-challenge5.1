# 해파리 간접 활용 아이디에이션과 CBL 선택지

> [!warning] 2026-08-22 팀 피드백으로 선도 가설 재검토 중
> 팀은 해파리 관측 결과보다 `출몰과 이동에 영향을 미치는 요인`을 중심으로 조사해야 한다고 판단했다. 이에 따라 이 문서의 JellyChaos 권고는 확정하지 않고, [[09) 해파리 출몰·이동 영향요인 조사 프레임]]의 종별·과정별 연구 설계를 다음 루프로 사용한다.

> [!summary] 수렴 결론
> 해파리를 경고할 대상이 아니라 **바다에서 육상 시스템으로 전달되는 실제 외부환경 이벤트**로 사용한다. 가장 강한 선도 가설은 이 이벤트를 시설 의존관계와 교차해 `확인할 곳 → 담당자 → 승인형 점검 작업 → 복기와 준비도`로 변환하는 **해양 카오스 엔지니어링 / 연안 중요시설 외부환경 운영 레이어**다.

관련 문서: [[04) CBL Engage 세션 01 - 협업 프로토콜과 초기 근거]] · [[06) 해파리 데이터 조사와 제품 후보]] · [[03) 공공가치 정의와 해커톤 적용 프레임]]

## 2. 문제를 다시 보는 한 문장

기존 1위였던 `해파리 도착시간·해수욕장/어업 행동 큐`는 이번 팀 요구와 직접 충돌하고, 주간 관측으로 6·12·24시간 ETA를 말하는 해상도 문제도 있다.

새 프레임은 다음과 같다.

```text
해파리 = 목적이 아니라 이벤트 원천
관측 + 해류 모델 = 불완전한 접근 가능성
시설·관측망·조직 = 이벤트가 시험하는 시스템
점검·승인·복기 = 실제 제품 행동
```

피치 훅:

> **우리는 해파리를 막지 않습니다. 해파리가 올 때 경북의 해안 인프라가 얼마나 준비됐는지 시험합니다.**

대안 훅:

> **해파리는 바다가 보내는 카나리아다. 우리는 그 신호를 경보가 아니라 검증 가능한 작업으로 바꾼다.**

## 3. Evidence Ledger

### 3.1 확인된 사실

### 3.2 2차 보도 — 독립 검증 미완료

- **E-05 / 신뢰도 B:** 2024년 신한울에서 하루 202t, 나흘 428t 해파리 유입과 대응 C→B가 있었다고 [SBS](https://news.sbs.co.kr/amp/news.amp?news_id=N1007783769)와 [뉴데일리](https://biz.newdaily.co.kr/site/data/html/2024/09/01/2024090100035.html)가 보도했다. 두 보도는 한수원이 국회의원에게 제출한 자료와 내부보고서를 인용하지만, 공개된 KHNP·원안위 원문은 확인하지 못했다. 따라서 구체 수치는 **확인 사실이 아닌 참고 단서**이며 모델 검증 라벨로 사용하지 않는다.

### 3.3 근거가 있는 해석

- 해파리 관측과 ROMS 흐름이 시설 방향으로 함께 움직이면 **차단 예측**이 아니라 `현장 확인 우선순위`의 보조 근거가 될 수 있다.
- 실제 사고가 없는 날에도 과거 이벤트 리플레이로 담당자·의존관계·승인 지연을 찾을 수 있다.
- 공공데이터를 조회 화면에 그치지 않고 표준 이벤트로 바꾸면 여러 공공 서비스가 재사용할 수 있다.
- 관측 공백과 데이터 신선도를 함께 노출하면 “관측되지 않음”과 “없음”의 혼동을 줄일 수 있다.

### 3.4 아직 검증되지 않은 가설

- NIFS 주간 출현률만으로 특정 시설의 취수구 폐색 확률이나 정확한 ETA를 계산할 수 있다.
- 해파리 출현이 발전 감발, 항만 지연, 보험 손실의 독립적 선행지표다.
- 해파리 이동이 살파·해조류·부유쓰레기 이동을 대표한다.
- 시설 운영자가 공개데이터 기반의 외부 검증 작업 큐를 실제 업무에 채택한다.

### 3.5 반드시 필요한 내부 데이터

실제 운영 정확도를 검증하려면 스크린 전후 차압, 취수 유량, 펌프 전류, 스크린 부하, 현장 생물량, 제거 중량·종, CCTV·음향센서, 조치 결과가 필요하다. 이 데이터가 없으므로 MVP는 `폐색 예측기`가 아니라 `근거 기반 확인·훈련 도구`다.

## 4. 아이디어 발산 지도 — 25개

### A. 중요 인프라와 운영

1. **JellyChaos / Marine Chaos Engineering** — 실제·과거 해파리 이벤트로 시설 의존관계와 담당자 준비도를 시험
2. **ColdSource Ops** — 취수시설별 감시·확인·점검 작업 큐
3. **IntakeGraph** — 취수 의존 시설에서 전력·산업·공공서비스로 이어지는 2차 영향 그래프
4. **ScreenCare Window** — 망·스크린 점검과 인력 선배치 가능시간 추천
5. **Heat × Jelly Grid Stress** — 폭염 전력수요와 연안 취수 외부환경을 겹친 스트레스 시나리오
6. **EastSea Mutual Aid** — 선박·그물·확인팀·수거 인력의 시설 간 공동 배치 시뮬레이션
7. **Incident Replay & SOP Lab** — 2003·2020·2021·2024 사건을 원인 종과 근거 등급을 필수 표기해 훈련 시나리오로 재생. 살파 사건은 해파리 모델 검증에 사용하지 않음

### B. 해양 관측과 과학

8. **Nature Probe** — ROMS 예상 이동과 관측의 잔차를 다음 조사 위치의 단서로 사용
9. **Blindspot Bounty** — 관측 공백과 불확실성이 큰 해역에 조사 임무 배정
10. **Blue Needle** — 오염을 진단하지 않고 제한된 수질·eDNA 표본 채취 위치만 추천
11. **Zero Is Data** — “미관측”과 “관측했으나 없음”을 구분하는 부재 관측 생성기
12. **SightTrust** — 신고·목시·트롤·모델의 출처별 신뢰도 원장
13. **Ecosystem Regime Sentinel** — 장기 수온·염분·종 조성의 공동 변화점 탐색
14. **Why Now Navigator** — 출현 변화의 가능한 환경 가설과 필요한 추가 검증을 제시

### C. 데이터 인프라와 품질

15. **CoastOps Event Fabric** — NIFS·ROMS·부이를 근거와 불확실성이 포함된 표준 해양 이벤트로 변환
16. **Ocean Data SLA Guard** — API 지연·결측·필드 변경·출처 충돌 감시
17. **Marine Anomaly Kernel** — 적조·고수온·유류·부유물 모듈이 붙는 범용 연안 이벤트 엔진
18. **Evidence-aware Briefing Copilot** — 사실·추론·미확인을 분리한 상황 브리핑 생성
19. **Situation-to-SOP Compiler** — 주간보고 자연어를 승인 가능한 역할별 작업 카드로 변환

### D. 지역행정·항만·공급망

20. **Coastal Relay** — 상류 해역의 이벤트를 하류 시설 확인팀에 전달하는 기관 간 선행 통보
21. **Role Router** — 사건 유형·지역·권한에 따라 담당 부서와 확인 책임자 배정
22. **Common Situation Timeline** — 해양환경·발전상태·항만운영·현장확인을 하나의 근거 시간축으로 보존
23. **Port Resource Cue** — 피해 예측이 아니라 확인 선박·청항선·인력 배치 우선순위 제공
24. **Coastal Site Due Diligence** — 신규 해수 취수 의존시설의 장기 외부환경 노출 비교
25. **After-Action Experiment Manager** — 오탐·기각·확인 결과로 임계값과 SOP 개선 실험 관리

> [!warning] 보류할 참신한 후보
> 해파리를 해류의 완전한 수동 부표로 간주한 쓰레기 이동, 유실어구, 오염 확산 예측은 종별 자체 운동·수직 이동·관측 편향 때문에 근거가 약하다. 보험금 자동지급·요율 산정도 손실 라벨이 없어 3일 MVP 범위를 벗어난다.

## 6. 3일 MVP

### Day 1 — 데이터 생존성과 사건 표준화

- NIFS 해파리 API, ROMS, 과거 출현보고를 연결한다.
- `observed_at`, `issued_at`, `valid_window`, `ingested_at`, `source`, `geometry`, `confidence`, `limitations`를 보존한다.
- 경북 해안을 5km 구간으로 나누고 한울·월성은 공개된 거친 위치 또는 가상 시설로만 표시한다.
- 키·좌표·최신 API 실패 시 NIFS 과거 **해파리 관측** 리플레이로 즉시 축소한다. 시설 사건 카드는 2020년 공식 해파리 사례와 2024년 B등급 보도만 별도 표시하며, 2003·2021 살파 사건은 원인 구분 교육에만 쓰고 해파리 모델 검증에서 제외한다.

### Day 2 — 판단에서 행동으로

화면은 네 개로 제한한다.

1. **근거 시계:** 출처, 발표시각, 데이터 나이, 결측
2. **접근 가능성 지도:** 각 원천 데이터의 발표·유효 주기 안에서 계산한 공간적 접근 가능성 띠와 불확실성. 주간 NIFS 자료로 시간 단위 ETA를 산출하지 않는다.
3. **시설 근거 카드:** 공식 상태, 확인 필요 이유, 금지된 해석
4. **승인형 행동보드:** 담당자, 작업, 상태, 근거

상태전이:

```text
관측됨 → 모델링됨 → 검토대기 → 사람 승인
→ 현장확인 요청(모의) → 확인 / 미확인 / 오탐
→ 종료 / 재평가
```

### Day 3 — 리플레이와 측정

측정 가능한 것:

- API 성공률·결측률·데이터 신선도
- 모든 판단에 출처·발표시각·불확실성이 붙은 비율: 목표 100%
- 과거 출현 좌표 시간분할에서 다음 해안 구간의 Top-K 적중률·거리오차
- 모의 신호→승인 시간, 작업 완료율, 운영자 기각·수정률, 오출동 수
- 리플레이에서 발견된 미지정 책임자·확인되지 않은 의존관계 수

측정 불가능한 것:

- 실제 취수구 폐색 확률과 ETA MAE
- 발전정지 방지 효과
- 살파·해조류·쓰레기에 대한 정확도
- 실제 기관 대응시간 단축

## 7. 안전·책임 경계

- `원전 안전 예측`, `발전 정지 예측`, `자동 제어`라고 부르지 않는다.
- 출력은 `위험 확정`이 아니라 `접근 가능성·현장확인 우선순위`다.
- `고위험 → 자동정지` 전이를 만들지 않는다.
- 공개 화면에는 상세 취수구 구조, 차단망 위치, 취약점, 내부 연락망을 표시하지 않는다.
- 실제 기관 명의 발송이나 외부 통보는 협업 프로토콜 I3 승인 전 금지한다.
- 제품 범주는 `생물유입 운영 레이어`로 확장할 수 있지만 MVP 예측 모듈은 **해파리만** 다룬다.
- 2021 사건을 해파리 사건으로 말하지 않는다.

## 8. Engage 선택지 — 팀이 고를 것

### 트랙 A — 인프라 회복탄력성 (권고)

- Big Idea 후보: **생태 데이터를 이용한 공공 인프라 회복탄력성**
- Essential Question 후보: **예측하기 어려운 자연 현상을 어떻게 지역 인프라의 사전 준비 능력으로 바꿀 수 있을까?**
- Challenge 후보: **경북 동해안의 실제 해파리·해류 공공데이터를 이용해 영향 가능 시설과 역할별 확인 작업을 생성하고 대응 준비도를 측정하는 작동 프로토타입을 만든다.**

### 트랙 B — 보이지 않는 관측 공백

- Big Idea 후보: **관측되지 않은 것을 아는 법**
- Essential Question 후보: **우리가 세지 못한 것과 실제로 없는 것을 어떻게 구별하는가?**
- Challenge 후보: **경북 연안 관측의 공백과 불확실성을 드러내고 다음 조사 위치를 추천하는 프로토타입을 만든다.**

### 트랙 C — 공공데이터 운영 인프라

- Big Idea 후보: **데이터가 행동으로 바뀌는 조건**
- Essential Question 후보: **공공기관은 언제 ‘아직 모른다’고 말하면서도 행동할 수 있는가?**
- Challenge 후보: **분절된 해양 공공데이터를 근거와 불확실성이 보존된 표준 이벤트로 바꾸고 한 개의 실제 행정 워크플로를 작동시킨다.**

> [!question] 다음 팀 결정
> A·B·C 중 하나를 고르고, Big Idea·Essential Question·Challenge를 팀의 말로 다시 써야 한다. 그 전까지 Investigate 진입은 보류한다.

## 9. 제출용 선도 가설 — 확정 전 초안

제품 작업명 후보:

- **JellyChaos — 해양 카오스 엔지니어링**: 기억에 남고 데모 서사가 강함
- **EastSea Pulse**: 지역성과 확장성이 좋음
- **Blue Canary**: 해파리의 간접 신호 역할이 선명함
- **ColdSource Ops**: B2B·운영 제품으로 정확하지만 다소 딱딱함

한 문장 정의:

> **해파리를 위험지도에 그리는 대신, 실제 해양 이벤트를 시설 의존관계와 교차하여 운영자가 승인할 수 있는 현장확인·점검 작업으로 바꾸고 경북 연안 중요시설의 대응 준비도를 측정한다.**
