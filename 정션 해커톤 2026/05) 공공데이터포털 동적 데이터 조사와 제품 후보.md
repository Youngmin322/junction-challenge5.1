# 공공데이터포털 동적 데이터 조사와 제품 후보

> [!summary] 조사 결론
> 공공가치, 3일 구현 가능성, 데이터 동적성, AI가 바꾸는 행동, 경상북도 결합 가능성을 함께 평가했을 때 **농업 기상·병해충·수자원·가격 데이터 조합**이 가장 강하다. 3일 MVP는 농업 전반을 다루지 않고 `특정 경북 주산작물의 공동방제·현장점검 우선순위` 또는 `저수율·기상 기반 관개 우선순위` 하나로 제한하는 편이 안전하다.

> [!warning] 검증 상태
> 포털 상세 페이지, 메타데이터, Swagger 구조와 일부 실제 API 엔드포인트의 도달성까지 확인했다. 그러나 이 조사 세션에는 발급된 공공데이터포털 ServiceKey가 없었으므로 라이브 데이터 행을 받지는 못했다. 키가 없는 요청에서 `401 SERVICE_KEY_IS_NULL` 또는 `403 SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 정상적으로 반환되는 것까지 확인했다. 따라서 `최신 관측시각`, `경북 totalCount`, `결측률`, `시군 커버리지`는 키 발급 직후 다시 측정해야 한다.

## 1. 조사 목적과 범위

### 조사 질문

> 누구의 어떤 공공문제를, 어떤 동적 공공데이터에 근거해, 어떤 판단·행동 변화와 측정 가능한 경상북도 지역 효과로 연결할 수 있는가?

### 조사 방식

- 공공데이터포털의 데이터 목록, 개별 OpenAPI 상세 페이지, 표준데이터셋 페이지와 Swagger 메타데이터를 확인했다.
- 별도 Codex 세션 `01a02446-50b9-76e0-8a49-c809ea7c002d`에 탐색 기준, 공공가치 해석, 동적 데이터 판정과 최종 후보 순위를 반복 질의했다.
- 메인 조사와 병렬 서브에이전트를 이용해 농업, 교통·공공서비스, 환경·재난, 지역경제·행정 분야를 나눠 탐색했다.
- 약 50개 후보를 확인하고 그중 구현 가능성이 높은 후보를 상세 검증했다.
- 사용자가 요청한 대로 OpenAPI와 표준데이터셋을 우선하되, 표준데이터는 주로 실행 자원·공간 결합 레이어로 평가했다.

### 조사 기준의 변화

초기에는 재난·안전과 취약계층 데이터에 무게가 실렸으나, [[03) 공공가치 정의와 해커톤 적용 프레임]]을 다시 기준으로 삼아 특정 분야가 아니라 **공공가치 증거사슬**을 중심으로 범위를 재설정했다. 이후 팀원 의견에 따라 정적 시설 목록보다 동적 상태·이벤트·수요·가격 데이터를 우선했다.

## 2. 공공가치 기반 데이터 역할

하나의 제품 후보에서 모든 역할을 서로 다른 데이터셋이 맡을 필요는 없다. 하나의 데이터셋이 여러 역할을 동시에 수행할 수 있다.

| 코드 | 데이터 역할 | 확인 질문 | 예시 |
| --- | --- | --- | --- |
| A | 수요·심각성·기준선 | 문제가 얼마나 크고 누구에게 발생하는가? | 피해량, 대기시간, 인구, 폐업 추세 |
| B | 동적 판단 신호 | 지금 무엇의 우선순위를 바꿔야 하는가? | 기상, 병해충, 가격, 운행, 위험도 |
| C | 실행 자원·채널 | 추천 뒤 실제로 무엇을 배치·조정·연결할 수 있는가? | 차량, 노선, 저수지, 지원사업, 시설 |
| D | 영향 측정 | 행동 전후 어떤 지역 결과가 달라졌는가? | 대응시간, 접근률, 피해면적, 가격 변동성 |
| E | 결합 기반 | 서로 다른 데이터를 무엇으로 연결하는가? | 행정코드, 좌표, 기관·시장 ID, 시각 |

### 우선 탐색 구조

```text
A 문제 규모·기준선
        ↓
B 동적 판단 신호 ──→ AI 우선순위·분류·예측
        ↓
C 실행 자원·행정 채널 ──→ 사람 또는 기관의 행동
        ↓
D 결과·지역 영향 측정

E 행정코드·좌표·시각·기관 ID가 전체를 연결
```

## 3. 동적 데이터 판정

OpenAPI라는 이유만으로 동적 데이터가 되는 것은 아니다. 다음 세 조건을 모두 만족할 때 동적 데이터로 분류했다.

1. 관측·발생·등록·변경 시각을 나타내는 필드가 있다.
2. 동일 대상의 반복 관측 또는 새로운 이벤트가 누적된다.
3. 데이터 변화가 문제의 의사결정 주기 안에서 다른 행동을 유발한다.

예를 들어 시설 위치를 OpenAPI로 조회해도 시설 목록이 거의 변하지 않으면 정적 데이터다. 반대로 월별 파일이라도 매월 자원 배분이나 점검 우선순위를 바꿀 수 있으면 동적 데이터가 될 수 있다.

### 이번 조사 우선순위

1. 실시간·10분·시간·일 단위 OpenAPI
2. 월별 반복 관측 OpenAPI와 표준데이터
3. 실행 가능성을 결정하는 시설·노선·자원 표준데이터
4. 정적 통계·시설 위치 파일

### 정적 데이터가 핵심이 될 수 있는 예외

- 빈집·노후시설처럼 문제 대상 자체가 천천히 변하는 경우
- 노선망·행정경계·시설 수용력처럼 실행 가능성을 결정하는 구조 데이터
- 접근성·입지·커버리지·자원 배치를 최적화하는 문제
- 지원 자격·관할 기관처럼 행동의 제약조건을 정의하는 데이터
- 프로토타입이 정적 자원 목록을 이용해 실제 배정·매칭·점검 행동을 바꾸는 경우

단순 지도 표시나 시설 검색은 해당하지 않는다.

### 1위 — 농업 기상·병해충·수자원·가격

**제품 판단 단위**

- 직접 사용자: 시군 농업기술센터, 공동방제 담당자, 농업용수 관리기관, 공영도매시장 출하 지원 담당자
- 최종 수혜자: 경북의 특정 작물 재배 농가와 해당 지역 농산물 공급망 참여자
- 핵심 질문: “오늘 또는 앞으로 1~3일 안에 어느 지역·작물부터 현장 점검, 공동방제, 용수 조정, 출하 지원을 해야 하는가?”

**높게 평가한 이유**

1. 경북의 산업구조와 직접 맞닿아 있다. 단순히 전국 농업 데이터를 보여주는 것이 아니라, 시군·작물·필지·저수지·시장 단위로 경북의 과수와 밭작물 문제를 좁힐 수 있다.
2. 동적 데이터의 시간 해상도가 서로 보완적이다. 10분~시간 단위 기상, 반복 수집되는 병해충 관측, 일 단위 저수율, 거래 시점별 경매 가격·물량을 함께 쓰면 즉시 대응과 며칠 뒤 계획을 모두 만들 수 있다.
3. AI의 결과가 설명이나 알림에서 끝나지 않는다. 위험 점수에 따라 현장 점검 순서, 공동방제 후보 권역, 관개 우선순위, 출하·저장 지원 대상을 정하는 업무 목록으로 변환할 수 있다.
4. 효과 측정 데이터가 같은 체인 안에 있다. 경보 후 현장 확인까지 걸린 시간, 점검 완료율, 저수율 하락 완화, 다음 관측의 병해충 발생 변화, 경매 가격·물량 변동을 후속 지표로 삼을 수 있다.
5. 병해충·용수·가격 중 하나만 골라도 MVP가 성립하며, 이후 다른 축으로 확장하기 쉽다. 해커톤에서는 세 축을 모두 구현하기보다 `병해충 선제 점검` 또는 `농업용수 배분` 하나를 주 행동으로 고정하는 편이 안전하다.

**감점한 이유**

- 농경지전자지도와 병해충 관측의 실제 최신일, 경북 행 수, 작물별 관측 밀도를 아직 인증키로 확인하지 못했다.
- 주소·PNU·격자·저수지 수계·시장 산지코드를 연결하는 공간 조인이 필요해 단순 API 결합보다 전처리 부담이 크다.
- 공동방제나 용수 배분의 실제 명령·접수 채널은 공개데이터에 없다. 프로토타입은 담당자용 작업 큐와 승인 화면까지 만들고, 자동 실행을 주장하지 않아야 한다.
- 기상과 병해충의 상관관계만으로 피해 방지를 인과적으로 입증할 수는 없다. 모델 신뢰도와 현장 확인 상태를 분리해 표시해야 한다.

**1위인 결정적 이유**

농촌 이동보다 경북 데이터 커버리지 불확실성이 작고, 산불보다 오판의 책임과 운영 진입장벽이 낮으며, 상권 후보보다 `판단→현장 행동→후속 관측`의 시간이 짧다. 공공가치·동적성·실행 가능성이 한쪽으로 치우치지 않은 가장 균형적인 후보다.

**순위 하락 조건**

- 병해충 API의 경북 최신 관측이 희소하거나 수개월 이상 지연됨
- 저수지 수위·저수율 데이터가 목표 지역에서 연속적으로 확보되지 않음
- 필지 또는 읍면동 수준으로 위험 신호를 연결할 수 없음

이 경우 병해충 축을 버리고 `기상+저수율 기반 농업용수 운영`으로 축소할 수 있지만, 이 대안도 실패하면 2위 이하로 내려간다. 현재 확신도는 **중상**이다.

### 2위 — 농촌 이동지원·버스·인구·공공시설

**제품 판단 단위**

- 직접 사용자: 시군 이동지원센터, 교통행정 담당자, 보건·복지 현장 담당자
- 최종 수혜자: 농촌 주민, 장애인·고령자, 학생, 통근자 등 정해진 시간에 필수시설에 도달해야 하는 사람
- 핵심 질문: “현재 어느 권역에 차량을 대기시키고, 어느 시간대에 행복택시·수요응답형 교통·셔틀을 보강해야 필수서비스 접근 실패를 줄일 수 있는가?”

**높게 평가한 이유**

1. 공공가치의 수혜자와 결과 지표가 가장 명확하다. 평균·상위 10% 대기시간, 배차 성공률, 차량 가용률, 버스 도착 오차, 30분 내 병원·행정·교육시설 접근 가능 인구를 측정할 수 있다.
2. 차량 위치·가용 상태와 버스 도착정보는 분 단위로 변하므로, 예측 결과에 따라 대기 차량 위치와 보완 교통수단을 바꿀 실익이 크다.
3. 월별 인구와 시설 위치 같은 느린 데이터가 실시간 이동 신호를 보완한다. 즉, 정적 시설지도 자체가 제품이 아니라 어느 수요를 먼저 충족할지 정하는 제약조건으로 쓰인다.
4. 교통뿐 아니라 의료·문화·행정 접근성으로 공공가치를 확장할 수 있어 발표 시 문제 정의가 쉽다.

**감점한 이유**

- 전국교통약자이동지원센터 API에 실제로 참여하는 경북 센터 수와 차량 상태 갱신 주기를 아직 확인하지 못했다.
- TAGO 버스도착 API가 경북 모든 군 지역을 지원한다고 가정할 수 없다. BIS가 없는 지역은 실시간 도착정보가 비거나 정확도가 낮을 수 있다.
- 실시간 차량 데이터만으로는 실제 이동 수요를 알 수 없다. 개인 호출 이력은 개인정보와 기관 협력이 필요하므로, 공개데이터만으로 수요예측을 과장해서는 안 된다.
- 차량·정류장·행정동·시설의 식별체계가 달라 경로 탐색과 공간 조인이 필요하다. 3일 안에는 한 시군과 2~3개 필수시설 유형으로 범위를 제한해야 한다.

**2위인 결정적 이유**

공공가치 점수는 농업보다 높지만, 핵심인 경북 차량 가용 데이터와 군 지역 버스 커버리지가 불확실해 구현·품질 점수가 낮다. 반대로 이 두 API에서 충분한 경북 실측 행이 확인되면 농업을 제치고 1위가 될 수 있다.

**순위 상승·하락 조건**

- 상승: 경북 복수 시군의 차량 위치·가용 상태가 5~10분 이내로 갱신되고, 실제 이동지원센터가 데이터 활용 의사를 보임
- 하락: 차량 데이터가 정적 기관 목록 수준이거나 TAGO 지원 지역이 경북 주요 대상지와 맞지 않음

현재 확신도는 **중간**이다.

### 3위 — 산불 위험·기상·소방자원·교통

**제품 판단 단위**

- 직접 사용자: 산림·산불 예방 담당자, 소방 관제·현장 지휘 담당자
- 최종 수혜자: 산림 인접 주민, 농가, 관광객, 지역 산업과 생태계
- 핵심 질문: “앞으로 3~72시간 동안 어느 시군·시간대에 순찰, 소방용수 점검, 물탱크차 또는 인력을 먼저 배치해야 하는가?”

**높게 평가한 이유**

1. 인명·재산·산림 피해 회피라는 공공가치가 가장 크고 경북 지역성과도 강하다.
2. 산불위험예보가 3시간 간격으로 72시간을 전망하고, 단기예보의 풍속·강수와 결합할 수 있어 선제 배치에 필요한 시간 여유가 있다.
3. 소방용수 위치, 도로 교통량, 과거 산불의 진화시간·피해면적을 결합하면 단순 위험지도가 아니라 `도착시간과 자원 공백을 고려한 배치 순번`을 만들 수 있다.
4. 예측 ETA와 실제 도착시간, 배치 승인시간, 진화시간, 피해면적, 고위험 지역 커버율처럼 결과 측정 방법이 비교적 선명하다.

**감점한 이유**

- 산불과 출동 판단은 고위험 영역이다. 모델이 잘못된 우선순위를 제시하면 실제 피해가 커질 수 있으므로 자동 지시가 아니라 담당자 승인용 의사결정 보조로 한정해야 한다.
- 공개 소방용수 데이터는 시설 위치와 제원 중심이며, 현재 사용 가능 여부·고장·수량·현장 장비의 실시간 가용 상태를 보장하지 않는다.
- 과거 산불위험지도와 유사한 서비스가 이미 많다. `예보 표시`만 구현하면 차별성이 거의 없고, 자원배치 순번과 예상 도착시간까지 보여줘야 한다.
- 산불위험 API의 포털 메타 시간범위가 오래되어, 현재 72시간 레코드가 실제로 반환되는지 키 발급 후 재검증해야 한다.
- 실전 배치·출동 데이터는 기관 협력 없이 얻기 어렵기 때문에 해커톤에서는 효과 측정을 시뮬레이션해야 할 가능성이 크다.

**3위인 결정적 이유**

공공가치만 보면 1위지만, 운영 책임·현장 자원상태 부재·기존 위험지도와의 차별화 때문에 구현과 참신성에서 감점됐다. 실제 산림·소방 운영 파트너나 차량·인력 가용 데이터가 확보되면 1위권으로 올라갈 수 있다.

**순위 상승·하락 조건**

- 상승: 관제 파트너가 제공하는 자원 가용 상태 또는 과거 출동·도착 기록을 결합할 수 있음
- 하락: 산불위험 API의 현재 레코드가 불안정하거나 결과물이 위험도 색칠 지도에 머묾

현재 확신도는 **중간**이다.

### 4위 — 폭염 영향예보·쉼터·교통·응급자원

**제품 판단 단위**

- 직접 사용자: 재난안전·보건 담당자, 지자체 상담원, 이동지원 담당자
- 최종 수혜자: 고령자에 한정하지 않고 야외노동자, 농촌 주민, 관광객, 대중교통 이용자 등 폭염 노출 인구
- 핵심 질문: “어느 지역·시간대·활동군에 먼저 연락하고, 어느 운영 중인 쉼터나 대체 의료기관으로 이동을 지원해야 하는가?”

**높게 평가한 이유**

1. 영향예보가 단순 기온이 아니라 보건·산업·농업 등 분야별 위험 단계를 제공해 행동 문구와 우선순위를 만들기 쉽다.
2. 단기예보·대기질·쉼터·저상버스 도착·응급실 가용병상을 결합하면 위험 감지부터 대피·이동·의료 대체까지 하나의 사용자 흐름을 빠르게 시연할 수 있다.
3. 공개 API 구조가 비교적 단순해 다섯 후보 중 3일 프로토타입 성공 가능성이 가장 높다.
4. 위험 발표부터 연락·이동까지 걸린 시간, 대체시설 연결 성공률, 고위험 시간대 응급실 가용병상 변화 등을 운영지표로 정의할 수 있다.

**감점한 이유**

- 폭염 알림, 쉼터 지도, 병원 검색 서비스가 이미 많아 단순 결합만으로는 차별성이 약하다.
- 쉼터 데이터에 실제 개방 여부·실시간 혼잡도·냉방 고장 상태가 없을 수 있다. 정적 명단을 “지금 이용 가능”으로 표현하면 위험하다.
- 수혜자 연락처와 이동지원 접수 채널은 공개데이터가 아니다. 기관 협력 없이 구현하면 결국 추천 화면에서 끝날 수 있다.
- 응급실 병상은 지연·공란이 있을 수 있어 이송의 유일한 근거로 사용하면 안 된다.
- 영향예보는 위험이 예상될 때만 발표될 수 있어 무응답을 안전 상태로 오인하지 않도록 단기예보와 결측 상태를 분리해야 한다.

**4위인 결정적 이유**

만들기는 가장 쉽지만, 독창적인 AI 판단과 실제 실행 채널이 약하면 `또 하나의 알림·지도`로 보일 위험이 크다. 반대로 지자체의 실제 연락·이동지원 업무 흐름이나 실시간 쉼터 운영정보를 확보하면 2~3위권으로 올라갈 수 있다.

**순위 상승·하락 조건**

- 상승: 쉼터 개방·수용 상태와 시민 연락·이동지원 접수 채널을 연결할 수 있음
- 하락: 쉼터와 병원 데이터가 현재 상태를 반영하지 못하고, 산출물이 시설 추천에 머묾

프로토타입 구현 확신도는 **중상**, 실제 공공효과 확신도는 **중간**이다.

### 5위 — 상권 변화·인구·민원·지원사업

**제품 판단 단위**

- 직접 사용자: 시군 소상공인 지원기관, 지역경제·도시행정 담당자
- 최종 수혜자: 소상공인, 근로자, 상권 이용 주민
- 핵심 질문: “최근 폐업·이전·민원이 함께 증가한 동네 중 어디를 먼저 점검하고, 어떤 지원사업이나 조달 기회와 연결해야 하는가?”

**높게 평가한 이유**

1. 상가의 생성·수정·삭제 이벤트, 월별 인구, 날짜별 민원, 일별 지원사업 공고를 결합할 수 있어 데이터 양과 주제 확장성이 크다.
2. 안전·취약계층 중심 문제에서 벗어나 지역경제라는 다른 공공가치를 제시할 수 있다.
3. 동네별 변화 징후를 탐지해 지원 공고 매칭, 현장 방문, 상담 우선순위를 만드는 MVP는 3일 안에 구현 가능하다.
4. 다음 달 상가 변화, 반복 민원, 상담·지원 연결 완료율을 추적하면 최소한의 운영 성과를 볼 수 있다.

**감점한 이유**

- 상권 변화와 행정 개입 후 지역 회복 사이의 시간이 길고 외부 요인이 많아, 해커톤 기간에는 인과효과를 보여주기 어렵다.
- 지원사업 공고에는 신청·선정·집행·성과가 없으므로 “매칭했다” 이후의 실제 효과가 끊긴다.
- 상가업소번호는 분류체계 개편 때 재생성될 수 있어 장기 생존·폐업 추적이 왜곡될 수 있다.
- 민원빅데이터는 공공누리 제2유형으로 상업적 이용이 제한되며, 지원사업 공고는 제3유형으로 변경금지 조건이 있다. 데모 이후 사업화 시 저장·요약·재가공 방식을 별도로 검토해야 한다.
- AI 역할이 공고 요약이나 단순 분류에 머물면 일반 챗봇과 차별화되지 않는다. `어떤 지역에 누가 언제 개입할지`를 결정하는 작업 큐가 반드시 필요하다.

**5위인 결정적 이유**

데이터 풍부성과 비안전 분야의 차별성은 좋지만, 행동 이후 성과를 공개데이터만으로 닫기 어렵다. 다른 후보보다 효과 귀속이 약하고, 라이선스와 식별자 연속성 위험도 있다. 다만 지자체가 상담·신청·선정·폐업 결과 데이터를 제공하면 순위가 크게 상승할 수 있다.

**순위 상승·하락 조건**

- 상승: 지역 파트너가 지원 신청·선정·후속 상담·폐업 결과를 제공해 D단계를 닫을 수 있음
- 하락: 상가 ID 연속성이 낮거나 민원·지원사업 라이선스가 원하는 제품 흐름과 충돌함

현재 확신도는 **중하**이다.

## 10. 제품 조합안

### 10.1 최종 권장 — 경북 농업용수·병해충 대응 코파일럿

#### 공공가치 증거사슬

| 단계 | 내용 |
| --- | --- |
| 직접 사용자 | 시군 농업기술센터, 공동방제 담당자, 농업용수 담당자 |
| 최종 수혜자 | 선택한 경북 주산작물 재배 농가와 지역 농업 생태계 |
| 공공 수요 | 병해충·이상기상·가뭄에 대응할 현장점검과 방제·용수 자원이 제한됨 |
| 데이터 | 단기예보, 팜맵 병해충, 저수지 일별 수위, 필요 시 농업기상 상세 |
| AI 개입 | 필지·읍면별 위험을 설명 가능한 점수로 산정하고 점검·공동방제·관개 우선순위를 생성 |
| 행동 | 담당자가 우선 점검지역·공동방제 일정·절수 안내 순서를 검토·확정 |
| 즉시 결과 | 오늘 또는 7일 안에 처리할 작업목록과 근거 제공 |
| 지역 영향 | 조치시간 단축, 불필요 관수·출동 감소, 병해충 확산·저수율 하락 위험 감소 |
| 측정 | 경보→조치시간, 7일 저수율 변화, 점검완료율, 병해충 관측값 변화 |

#### 3일 MVP 범위

- 작물 1개
- 경북 시군 1~2곳
- 행동 1개: `공동방제·현장점검 우선순위` 또는 `관개 우선순위`
- 실제 데이터 2~3개
- 담당자 승인 전제의 작업목록 화면
- 예측 정확도보다 데이터 연결, 근거 설명, 행동 완주를 우선

#### 실패 조건과 축소안

| 실패 조건 | 축소안 |
| --- | --- |
| 팜맵 병해충 최신 관측이 너무 오래됨 | 농촌진흥청 병해충 발생·예찰정보로 교체하고 시군 단위로 축소 |
| 필지 단위 경북 커버리지가 낮음 | 읍면 또는 시군 우선순위로 축소 |
| 저수지와 농지의 공급권역 결합키가 없음 | 수위 데이터는 시군 위험 근거로만 사용하고 직접 배분은 제외 |
| 데이터가 당일 승인되지 않음 | 기상청 단기예보 + 다운로드 가능한 표준데이터 조합으로 축소 |

### 10.2 농촌 이동권 운영 코파일럿

- 입력: 월별 통·반 인구, 정류장 수요, 실시간 버스도착, 이동지원센터 대기·가용차량
- 판단: 지역·시간대별 서비스 공백 점수
- 행동: 차량 대기 위치, DRT·행복택시 증차 시간, 복지·의료 셔틀 시간 조정 후보
- 측정: 평균·P90 대기시간, 가용차량 비율, 예정 대비 도착편수, 필수시설 30분 도달률
- 핵심 위험: 경북 시군 이동지원센터와 TAGO의 실제 커버리지

### 10.3 산불 선제 자원배치

- 입력: 3시간 산불위험예보, 강수·풍속, 소방용수, 교통 ETA
- 판단: 시군별 위험도와 자원 도달성
- 행동: 순찰·물탱크·점검 대상 임시배치 순번 제안
- 측정: 예상·실제 ETA, 진화시간, 고위험면적, 피해면적
- 안전: 실제 출동은 관제 담당자 승인 필수
- 차별화 조건: 위험지도·알림이 아니라 배치 순번과 근거·예상 도착시간까지 제공

### 10.4 폭염 운영 오케스트레이터

- 입력: 영향예보, 단기예보, AirKorea, 쉼터, 저상버스 도착, 응급실·AED
- 판단: 시군·시간대별 위험과 이용 가능한 대체 자원
- 행동: 이동지원·쉼터·대체시설 안내 작업목록
- 측정: 위험발표→접촉·이동 소요시간, 대체시설 연결 성공률
- 위험: 실제 수혜자 연락·서비스 채널은 포털 데이터에 없어 지자체 협력이 필요

### 10.5 지역경제 변화→지원 연결

- 입력: 상가 생성·수정·삭제, 월별 인구, 민원 급증
- 판단: 행정동별 지원 필요도와 변화 원인 후보
- 행동: 지원사업 공고·나라장터 사업과 연결할 담당자 검토목록
- 측정: 다음 달 상가·인구 변화, 민원 재발, 지원 연결률
- 위험: 공고는 선정·집행·성과가 아니며 상권 변화와 행정 개입의 인과관계가 길다.

## 11. API 접근·저장 설계

### 공통 저장 필드

동적 API는 다음 메타데이터를 함께 저장한다.

```text
source_dataset_id
source_endpoint
entity_id
region_code
observed_at
forecast_valid_at
source_updated_at
fetched_at
raw_payload_hash
quality_flags
```

### 예보와 관측 분리

- `observed_at`: 실제 관측 시각
- `forecast_issued_at`: 예보 발행 시각
- `forecast_valid_at`: 예보 대상 시각
- `fetched_at`: 우리 시스템이 받은 시각

이 네 시각을 섞으면 사후 검증과 데모 신뢰성이 무너진다.

### 경북 결합 키

| 유형 | 사용처 | 주의 |
| --- | --- | --- |
| 행정동·법정동 코드 | 인구·가뭄·상권·시설 | 행정구역 개편 브리지 필요 |
| 시군구 5자리 코드 | 산불·지역 통계 | API별 코드 체계 확인 |
| 좌표 | 팜맵·기상격자·시설·교통 | 좌표계와 주소 지오코딩 오차 확인 |
| PNU·필지 ID | 농업·건축물 | 개인정보 또는 개별 농가 식별 위험 검토 |
| 시장·기관·센터 ID | 경매·응급실·이동지원 | 기관 코드 마스터 별도 관리 |
| 수집·관측시각 | 모든 동적 API | API별 시간대와 포맷 통일 |

## 15. 사실·해석·미확정

### 확인된 사실

- 위 상세 후보의 공공데이터포털 페이지와 주요 메타데이터를 확인했다.
- 대표 REST 엔드포인트는 ServiceKey 없이도 서비스 라우팅까지 도달했다.
- ServiceKey가 없는 호출은 정상적으로 인증 오류를 반환했다.
- 다수 핵심 API는 개발단계 자동승인이며 무료다.
- OpenAPI의 포털 수정일과 실제 최신 관측시각은 서로 다른 개념이다.

### 팀 해석

- 농업 체인이 현재 가장 공공가치·지역성·AI 행동 연결이 균형적이다.
- 동적성 자체는 공공가치가 아니라 행동을 바꾸는 판단 재료다.
- 정적 표준데이터는 동적 신호를 실제 시설·자원에 연결할 때 가치가 있다.
- 해커톤에서 모델 정확도보다 실데이터와 행동 경로를 완주하는 것이 더 중요하다.

### 미확정

- 팜맵 병해충의 경북 최신 관측일과 실제 필지 커버리지
- 농업기상 관측지점의 경북 분포와 토양수분 결측
- 경북 공영도매시장의 최신 경매 이벤트 안정성
- 교통약자 이동지원 API의 경북 참여센터 범위
- TAGO 버스도착정보의 경북 군 단위 BIS 연계율
- 각 API의 실제 응답 지연·장애·호출 제한
- 변경금지·비상업 라이선스 데이터의 최종 제품 내 가공 허용범위
- 주최 측이 전국 데이터를 경북 필터링해 사용하는 방식을 인정하는 정확한 범위
